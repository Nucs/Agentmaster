# Agentmaster

> A fork of **Windows Terminal** (`microsoft/terminal`, MIT) that turns it into a manager
> for multiple **Claude Code** sessions.

## Development Rules

- Do not build, deploy or install without the user's permission.
- Every build writes to `Q:`, never to `K:`: a layout goes to a `Q:\agentmaster-layouts\<slot>` through `-LayoutDir`, and the build trees (`bin`, `obj`, the package's `bin` / `obj` / `AppPackages`) are junctions to Q: (*Building FAST* #1).
- Commit changes once done: one `git add` + `git commit` with an extensive message (*Commit Instructions* in the global guidance). Committing needs no permission; only build, deploy and install do.
- **This file describes the current state only.** Write no build state ("not built", "in production since"), dates, history ("before", "was", "used to", "no longer"), phases or provenance ("the user's request of …") into it: the *Builds* table says what each install runs, `git log` keeps the history, and the docs keep the reasoning.
- **Keep this file under ~250K characters.** A feature gets a short entry here and its detail in its doc under `doc/agentmaster/`; read that doc before changing the feature.

## What Agentmaster is

- One Windows Terminal–based app that manages **N Claude Code sessions across M working directories**, with full interaction in each session and complete programmatic control (inject prompts, read output, drive state).
- Each session is a real `claude.exe` on a **ConPTY** connection: a full-fidelity terminal with a shared stdin (the user and the orchestrator coexist), output tapped for the UI, and semantic state from **Claude Code hooks**, never from screen-scraping.
- **Design A, "Native Graft":** the management brain lives inside the fork (C++/WinRT).
- **The pipeline:** launch → `claude.exe` on a ConPTY → `--settings` hooks → PowerShell forwarder → named pipe → registry → state machine → UI; a reopened session resumes with `claude --resume`.
- **One engine per process** (Rule #10): `SharedEngine()` (`AgentMaster/Engine.{h,cpp}`) owns the registry, the hooks bridge, the scheduler, the transcript scanner and the Fleet Observer for every window (the WindowEmperor is one process with N windows); each window's Agent Manager page is a lens over that one fleet.
- **Two state sources:** hooks push turn events; the Fleet Observer and the transcript scanner pull process, presence and transcript facts, the always-correct floor under the lossy push.

## Features

### Agent Manager page (C1 UI)

Detail: [`AGENT_MANAGER.md`](doc/agentmaster/AGENT_MANAGER.md).

- **A page, not a tab.** Each window owns one `AgentManagerContent` (`_managerPage`, built by `_CreateAgentManagerPage` at first layout, never in `_tabs`); the tab strip's **Home** button is the only way in. `_ShowManagerPage` swaps the page's root into `_tabContent` and deselects the tab strip, so every tab-targeting action no-ops; `_managerPageVisible` is the one authority (`_GetFocusedTabIndex` answers `nullopt` while it is set). A window with zero tabs is legal and shows its page. An `agentManager` pane request is refused.
- **Home on the page** shows ↶ while a session this window hosts as a live tab is selected, and a click returns to that tab (`_ApplyManagerHomeButtonFace`, `_ManagerJumpBackSessionId`). ⚠ The FontIcon stays the button's direct Content, and the button gets no XAML tooltip. A click within the double-click time of a click that opened the page or jumped back is ignored.
- **The page shows by itself** when the last tab closes, when every remaining tab is dormant, when the focused tab is deactivated, and for a window that opens with no tab or reopens while on the Manager. `nextTab` / `prevTab` leave it for the first / last tab.
- **A launch made on the page** (the launch row, a card / tree / External menu's launches, the side panel's "+") opens its tab in the background, starts it in place and selects it on the page (`_LaunchFromManagerPage` → `_FinishManagerPageLaunch`).
- **Regions:** the **Triage Board** (cards in five state columns — Running · Waiting-for-you · Needs-approval · Error · Idle/Done — plus the observe-only External census), the **Explorer Tree** (working directories → sessions; LOCAL · GLOBAL · EXTERNAL, persisted per window; six sorts, one setting for every window: `treeSort`) and the **Prompt Queue** (beside a read-only Summary tab). Only open sessions show; closed ones live in the Sessions browser.
- **Linked Lenses:** a click selects; a double-click, tree `Enter` or the Prompt Queue's eye Activates (cross-window through the engine's activate sinks; the hosting window comes to the front); switching tabs selects the session on the page (`_SyncManagerSelectionToTab`); selecting drops the session's folder into the Launch box.
- **One session menu** for a board card, a tree row and a side-panel card: Jump to Tab, Rename, Deactivate ▸ and Close ▸ (the tab menu's scopes, run in the window that hosts the tab), Open New Session Here ▸ / Fork session ▸, Copy ▸, Show Transcript, Tags.
- **The launch row** (`AgentLaunchBar`, shared with the side panel's "+" card) validates as you type (a folder · a session id on disk → Resume / Fork · a creatable path → Create & Launch · invalid), opens a folder picker, and its Launch button carries a PRESETS hover menu. With the Claude⇄Codex toggle on Codex it takes folders only.
- **Rebuild cost** (⚠ Gotcha *The Manager lens is a full rebuild*): the board and tree rebuild only while the page is on screen (`SetLensVisible`), from live snapshots, with cost-paced gaps (`RefreshPacing.h`); the board's columns persist (`_EnsureBoardColumn`); menus fill on open. Route every lens trigger through `_Refresh`.
- **Toolbar:** Launch · Fork · Reopen Windows (N) · ⚙ · Pause Prompt Queue Runner · Sessions. The page is always dark (*Conventions*).

### Side panel

Detail: [`SIDE_PANEL.md`](doc/agentmaster/SIDE_PANEL.md).

- A fleet pane beside the terminal (docked left by default; ⇄ flips it, GLOBAL): session cards over the selected session's summary, LOCAL to the window by default (a per-window LOCAL/GLOBAL toggle).
- Each card wears the tab's status icon through `AgentStatusGlyph` (the dot, the draft's 3 dots, the unread ring blinking with its tab's, the spark crown). ⚠ It is the code twin of `TabHeaderControl`'s dot wrap: change both together.
- The card list is edited in place (a per-card model diff; `PlanKeyedListOps` moves the fewest cards) and virtualized (`AgentMaster/VirtualListWindow.h`); a card's rounded backgrounds are childless Borders, so a card adds no composition node.
- **Header:** **+** (a launcher card at the click, placed by `PlacePointerCard`, its folder list open), **Sum** (hides the summary area; with Sum off, hovering a card opens no rich card — deliberate; its `AgentSessionToolTipHost` stays attached, unused), LOCAL/GLOBAL, the sort, ⌖ (scroll the cards to the selected tab's card; GLOBAL, default ON), ⇄, collapse.
- A card peek ends only on a click into the terminal, or on focus coming from the terminal column or the panel; focus that a closing menu, dialog or overlay hands back does not end it.

### Per-tab link badge (overlay) and summary panel

Detail: [`TAB_OVERLAY.md`](doc/agentmaster/TAB_OVERLAY.md).

- Every tab the Fleet Observer classifies carries a top-right HUD (`AgentTabOverlay` in the terminal's slot `Grid`; off-switch `showTabOverlay`; dim at rest, bright on hover).
- **A linked Claude session:** row 1 — the state (Triage colors), `model · effort · kind`, the Prompt Queue Runner mode (Paused / Auto; `<mode> (Off globally)` while the global pause is on), the queued count, `⛓ linked`; row 2 — `<workdir folder>/<branch>` (the live branch, `ReadGitBranchForDir`); row 3 — `⏳ <next queued prompt>` (the first Pending prompt's first line, ≤ 300 chars), while something is queued.
- **Any other tab:** a dim `○ <kind> · unlinked` (pwsh / cmd / a claude not yet prompted / codex) that follows the tab's activity and becomes the linked badge on the session's first prompt.
- **Hover** reveals the controls (runner Paused ↔ Auto, Send-now, queue peek, Jump-to-Manager) and the action row: folder (Open Path), **mail** (moves the unsent draft into the queue and clears it from the box through the discard ladder; Shift+Click keeps it; enabled while a draft exists; Claude only), the copy menu (`CopySessionField`: Session Id, Path, Branch, Current Prompt, the launch CLI, Summary, Transcript ▸ Show + five levels) and the pencil.
- **The summary panel** (the pencil; GLOBAL `showSummaryPanel`): a drag-resizable second overlay below the badge rendering the `session-end.js` box from the transcript (`AnalyzeSessionTranscript`, off-thread, reloaded when the transcript grows): Parent / Plan, Tasks, Messages, Files read / edited. Its Messages cover the whole conversation — every earlier session it continues (a fork's parent, a plan-restart parent, a `/clear` predecessor, a `/handover` origin), numbered straight through under session separators (`fork <id8>` above a fork, `SummarySeparatorLabel`; ⏮ `summaryPanelShowHistory`, default ON); ↵ switches message newlines (`summaryPanelWrapNewlines`). System-injected "user" messages are filtered (`SeIsCommandNoise`).
- A fork with no messages yet shows its source's transcript in every summary and copy (`ResolveClaudeDisplayTranscript`).

### The tab strip

Detail: [`TAB_STRIP.md`](doc/agentmaster/TAB_STRIP.md).

- **The tab strip state dot** before each classified tab's title (`TabHeaderControl.xaml`, `TerminalTabStatus`, `_SetTabAgentDot`): a managed session wears its Triage color (Running blue · Waiting goldenrod · NeedsApproval orange-red · Error crimson · Done green · Idle gray), an observed tab a dim gray dot. The palette is `AgentStatusColors.h`. ⚠ `AgentManagerContent.cpp` keeps its own identical `StateColor` table for the board: change both.
- **On the dot:** the unread **flash ring** (a session left Running for Idle / Waiting / NeedsApproval on a tab that is not the focused tab of the active window; cleared by visiting the tab; `flashRingColor`; every ring blinks in lockstep through `AgentLockstepBlink` — ⚠ never set the ring's `Opacity`), the **3 dots** of an unsent draft, the **spark crown** (at rest while the server cache is still warm, `ServerCacheStillWarm`, polled), the **favorite marker** (Crown or Star, never part of the title) and the Manager page's **selection pill**. Tag ribbons hang below the tab.
- **Size:** `tabWidthMode` (Windows Terminal setting / Equal width / Fit to title / Compact), min / max width, title font, min height; a long title ends in "…" inside its tab.
- **Reveal and drag are Agentmaster's own:** the strip virtualizes and ignores bring-into-view requests, so `_RevealTabInStrip` is the only way to scroll to a tab; native MUX drag is off, and reorder, tear-out and cross-window docking are a pointer-owned gesture (Gotchas *The tab strip*).

### Notifications and the taskbar

Detail: [`NOTIFICATIONS.md`](doc/agentmaster/NOTIFICATIONS.md).

- **Toasts** when a managed session leaves Running (line 1 the title; line 2 `Has completed after <span> and is <status>`), fired once per transition by the window hosting the tab (`_EvaluateAgentNotification`). A Running → Idle / Waiting toast is held while external work (a subagent, a shell) is live and dropped if the session runs again; one shown toast per session per 20 s; a newer toast replaces the older (Tag + Group). ⚠ Open: an unpackaged copy shows no session toast (the no-arg `CreateToastNotifier()` needs package identity; logged once as `[notify] toast failed`), and `ToastActivator::IsRegistered()` reads true there too, so the in-process click fallback is never wired.
- **A click** foregrounds the hosting window and jumps to the tab through a per-identity toast COM activator (`AgentToastActivator.h`; its CLSIDs are in both manifests, so ⚠ a manifest change needs a re-register); a cold start arrives as `-ToastActivated -Embedding`, handled as a plain launch.
- **The taskbar unread count:** a red number on the taskbar button = the unread sessions of every window (`ITaskbarList3::SetOverlayIcon`, `TaskbarBadge.h`; counted process-wide by `Engine::PublishWindowUnreadSessions`).
- **The taskbar preview frame:** a window holding an unread tab shows its preview inside a flash-colored frame, through DWM iconic thumbnails (`TaskbarThumbnail.h`, `IslandWindow::SetTaskbarUnreadFrame`; ⚠ Gotcha *DWM iconic thumbnails*).

### The Sessions browser and favorites

Detail: [`SESSIONS.md`](doc/agentmaster/SESSIONS.md), [`FAVORITES.md`](doc/agentmaster/FAVORITES.md).

- **The only history view:** a full-window page (toolbar **Sessions**) listing every Claude Code session on disk (`~/.claude/projects/*/<uuid>.jsonl`) in a 1d–3mo window or a From/To range.
- **Search** runs in two phases: fast (per-session sidecar indexes `<profile>\sessions-index\<sid>.json` and `history.jsonl`) and slow (ripgrep-prefiltered transcript content, every match attributed in-process to 👤 typed prompts or 🤖 assistant text and tool I/O). Scopes 👤 🤖 📁 📄 🏷 (F); the query is whitespace-split AND terms, `"quoted"` is one exact phrase, and a pasted session GUID matches the session and its forks. Results rank in tiers: name > path > content.
- **Rows:** fork-aware created time, line-derived last activity (a transcript's mtime lies), title precedence `customTitle > aiTitle > summary > first real prompt`, msgs · tools, the tab-color chip, a presence ring, the ★ column and a Tags column. Up / Down walk the visible rows; the page focuses its search box on show.
- **Actions:** Jump; **Resume here** (`_ResumeSessionFromDisk`; restores the Prompt Queue); **Fork here** (`claude --resume <parent> --fork-session --session-id <new>`, the new id minted by Agentmaster; forking a live session is safe); Open New Session Here; **Edit Title** in place (right-click, or a slow double-click; an inline box, ⚠ not a ContentDialog); **Filter ▸** (same folder / branch / day / week / month / fork family; facets AND; a `✕ filter` chip); **📂 Folders** (the launch and inferred folders, recent vs most used; picks OR; the inference is an off-thread follow-up pass — ⚠ never inside the gather); **Hide from list** / Unhide (`hiddenSessionIds`; the Hidden checkbox shows them). Resume, fork and window restore open exactly the picked id.
- **Close and Favorite** are the lifecycle verbs: Close always archives (the record stays with `live=false`; nothing on disk is deleted); **★ Favorite** is the durable SessionStore `favorite` key, a ★ column and filter here and a crown or star on the tab.
- **The whole conversation:** the summary follows solid links backward only — a fork's parent, a plan-restart parent, and the `/clear` and `/handover` predecessors recorded on the session (`SessionInfo::continuedFromId` / `continuedVia`) — through `CollectConversationUpstream`. Nothing on disk names a session's successor.
- **Presence:** `TranscriptStore::ReadSessionPresence` reads `~/.claude/sessions/<pid>.json`; the observer validates each row against its process (`PresenceRowMatchesProcess`) and publishes `SessionInfo::presenceStatus` (a fact, never `SessionState`).

### The AI search and the agent harness

Detail: [`SESSIONS.md`](doc/agentmaster/SESSIONS.md) §9, [`SDK_HARNESS.md`](doc/agentmaster/SDK_HARNESS.md).

- **The AI search:** an **AI** toggle inside the Sessions search box (a sibling drawn over the box's right end; `_SessionsAiFitToggleIntoBox` pads the box and shifts its ✕ — ⚠ any control placed inside a `TextBox` this way must do both) turns it into a request line. A hosted Sonnet 5.5 searches, shows the sessions that fit (best first, a `why` under each) and answers in a strip under the header; ⊘ resets the conversation. One conversation per process (`SharedSessionSearchAgent`), shared by every window; the Telegram Search topic runs its own.
- **Tools** (in-process MCP servers, `SessionSearchTools`): `mcp__sessions__search` / `grep` / `read`; `mcp__display__show` (the only screen change); `mcp__tabs__overview` (every window's tabs as one Markdown page grouped by working folder) / `status` (what up to 32 sessions are doing now, and why the next queued prompt waits) / `list` / `resume` / `fork` / `deactivate`; every search row carries its `status` and its `age` by the MOST RECENT key, and the prompt sends any mention of a window, a tab or an open session to `overview` first. Guards in code: with more than one window and no `window`, resume and fork refuse and describe the windows; at most 5 opens and 1 deactivate per request; deactivate refuses an adopted tab, and a Running or NeedsApproval one without `cut_off_turn:true`.
- **The index:** one per process (`SharedSessionCatalogKeeper`), built for every session at start and never freed; a tool call waits up to 90 s for a complete, fresh index and never searches a partial one. Every session is searched by default; grep narrows each alternative by its required literals and runs one ripgrep over the projects folder.
- **The prompt** comes from `tools/ai-search-eval/pieces.txt` (`gen_prompt.py` → the `AM_PROMPT_*` macros; ⚠ edit the pieces, never the macros); the eval kit there scores recall per query. ⚠ The Debug dev bot understates search quality (the debug heap serializes the readers): judge on an optimized build.
- **Thinking level:** the strip's `thinking off` rotates off → low → medium → high → xhigh → max (`sessionsAiThinkingLevel`), applied live (`HarnessConversation::SetThinking`). "Off" on Sonnet 5.5 is the API's `between_tools`, sent through `CLAUDE_CODE_EXTRA_BODY`. ⚠ Every harness process starts `--thinking adaptive`, and the harness never sets `CLAUDE_CODE_EFFORT_LEVEL`.
- **The harness** (`AgentHarness.{h,cpp}`, `HarnessConversation`): one windowless `claude.exe` per conversation, driven through the pinned SDK submodule `refs/claude-agent-sdk-cpp` (stream-json, in-process MCP servers, `--tools ""`, no user settings / hooks / `CLAUDE.md`, `--no-session-persistence`, auto-compaction at 500K). Its record and digest live in `<profile>\harness\`; it ends its process 10 minutes after no page shows the search, and a new process continues from the digest.
- **Permissions:** always bypass, else auto, else `dontAsk`. Claude Code lowers a mode it does not allow without a word, so `SettlePermissionMode` reads the mode in effect and `Inventory()` reports it. ⚠ With bypass the tool list is the only limit: give a conversation a tool only when it may use it freely (the SDK's spurious `resources` capability is removed for that reason).
- The child carries `AM_HARNESS=<name>`; the Fleet Observer and the CLI skip it.
- **Known issue:** a superseded request's queued search still runs in full (SESSIONS.md §9.11).
- A build needs the submodule (`git submodule update --init refs/claude-agent-sdk-cpp`) and the vcpkg `nlohmann-json`. Logs: `[harness]`, `[harness-proc]`, `[ai-search]`, `[nav] sessions ai …`.

### The session database (DuckDB)

Detail: [`SESSIONS_DB.md`](doc/agentmaster/SESSIONS_DB.md).

- One DuckDB file per profile (`<profile>\sessiondb\sessions.duckdb`) holding every Claude Code session on the machine: every transcript line verbatim, ~110 facts per session, block text, touched paths, usage, Agentmaster's titles / tags / favorites / links, and its own full-text index.
- Owned by one process per profile, `agentmaster-sessiondb.exe` (DuckDB 1.5.6, pinned by SHA-256 in `tools\Get-DuckDb.ps1` + `sessiondb\duckdb.props`), serving a named pipe; the GUI never loads `duckdb.dll`. The app's transcript watcher feeds it the changed sessions every tick (`SessionDbRefresher`, default 5 s).
- **Off by default** (`sessionDbMode` Off / Shadow / On). On: the Sessions page's content search and the AI search use it; the CLI gains `search`, `sql`, `sessdb`; `agentmaster-sessiondb.exe mcp` is a stdio MCP server.
- Its three requirements are not met (DuckDB as the engine of both the page search and the agent, called in-process, a cold build under 30 s); the redesign and its open decisions (a)–(e) are SESSIONS_DB.md §17.
- ⚠ Gotcha *DuckDB's memory limit binds per transaction*.

### Transcripts and the summary jump

Detail: [`TRANSCRIPT_OVERLAY.md`](doc/agentmaster/TRANSCRIPT_OVERLAY.md), [`SUMMARY_JUMP.md`](doc/agentmaster/SUMMARY_JUMP.md).

- **Copy ▸ Transcript** (every copy menu, one table `kTranscriptCopyMenu`): the conversation as Markdown at five levels (Minimal · Compact · Default · Full · Max) through `TranscriptTurns`, a C++ port of the am-agentmaster-cli skill's `transcript_turns.py` v9, pinned byte for byte to goldens that script writes (`tests/turns/make_goldens.py` → `tests/turns/expected/`, `--preset v9`; `TestTranscriptTurns`). ⚠ A change in the skill's output means regenerating the goldens and porting the change. One option is Agentmaster's own and set by no level, so the goldens never see it: `TurnsOptions::editDiffs` (📜 All Screen's File diffs, MESSAGING.md §21.39; `TestTranscriptTurnsEditDiffs`). A Codex rollout falls back to the plain-text readers.
- **Show Transcript** (below Copy in every session menu; Copy ▸ Transcript ▸ Show): a reading view over the window (`AgentTranscriptOverlay`, cmark → `MarkdownBlocks`): a tab per level (it opens at the last level picked, `transcriptOverlayLevel`), each turn's tool calls folded, a ↵ line-wrap toggle (`transcriptOverlayWrapLines`), session-chain links. Esc, a click outside or any tab switch / move / drag closes it; while open it keeps focus inside the card.
- **The summary jump:** the ▸ beside each prompt in the summary centers the terminal on that prompt (the pure `PromptAnchor.h`, through `ControlCore::ResolveConversationPromptRow`). ⚠ Its periodic eligibility refresh stays gated (an epoch cache, the focused tab only, a 2m30s floor) so it can't peg the UI thread.

### Hooks and the state machine

Detail: [`HOOKS.md`](doc/agentmaster/HOOKS.md).

- **The engine** (`AgentMaster/`, plain C++, no WinRT): `SessionRegistry` (thread-safe, the single source of truth; token-based observers and adoption handlers), `HooksBridge` (named pipe `\\.\pipe\agentmaster.<pid>`), `ClaudeSpawn` (the spawn / `--resume` recipe, the hooks config, the PowerShell forwarder), `Scheduler`, `SessionScanner`, `ProcessObserver`. The fleet loads once per process behind `Engine::restoreMutex`: a second window waits until it is loaded.
- **Hook invocation:** for a `claude.exe` ≥ 2.1.139 (its PE file version, `SelectHookExecHost`) every forwarder hook is exec form (Windows PowerShell 5.1 by full path with an `args` array, no shell); an older or unknown claude gets the shell form. Timeouts 10 s, SessionEnd 5 s. Eight events, `PreCompact` and `PostCompact` included. All three writers of `hooks-settings.json` (engine init, every spawn, the cog's Save) pass the resolved `claude.exe`. The Stop forwarder takes the payload's `last_assistant_message`.
- **The wire line** (`HookWire.h`): six fields, then `tabToken` (the hosting `WT_SESSION`), the escaped `prompt` (UserPromptSubmit), `ts` (the hook's fire time; the arrival time when missing) and `source` (the SessionStart source / compaction trigger / SessionEnd reason, `SanitizeWireSource`).
- **The ordered state machine** (`NextSessionStateOrdered`, `SessionInfo.turns`): a Stop fired before the newest prompt, or one closing a turn shorter than `kMinRealTurnSpanMs` (2 s), keeps the state; a type-ahead prompt keeps the next Stop Running; only a prompt-carrying `UserPromptSubmit` stamps `turns.lastPromptUnixMs` or counts as type-ahead (an empty one is state-only); every UPS logs one `[ups]` disposition. Hook `ts` also refreshes the Waiting → Idle decay anchor `lastActivityUnixMs`.
- **The scanner** (`SessionScanner`, the PULL reconciler) is event-driven: `TranscriptWatcher` holds one `ReadDirectoryChangesW` watch on `<claude config>\projects` (an in-memory index of transcript paths and per-session change sequences); hot sessions (Running, NeedsApproval, a sent and unechoed prompt) are re-stat'ed every pass, cold ones on a change or a 30 s resync; an unhealthy watch falls back to polling. It reads ≤ 1 MiB per pass and judges a tail only once its cursor has caught up (`ScanState::readReachedEnd`); a fresh cursor on a big transcript starts at its tail window.
- **One state machine for push and pull.** The scanner synthesizes what hooks miss: `recon-stop` (a terminal tail quiet ≥ 2 s → WaitingForInput); an interrupt marker ends the turn; `recon-block` and claude's presence `waiting` → NeedsApproval, and back once answered (three independent belts); `recon-stop-idle` (claude's own idle heartbeat: 5 s for NeedsApproval, 30 s for a cleared Running tail); `recon-subagent` (side-file writes or a busy / shell heartbeat keep a session Running, also after the turn while a teammate, background agent or shell works); `recon-error`; `recon-cutoff` (every synth, its states and its guards: HOOKS.md *The pull reconcilers*). The turn-start race guard holds `recon-stop`, `recon-stop-idle` and `recon-error` while a submitted prompt has not reached the transcript (`NewerPromptNotYetInTranscript`, ≤ 30 s). The answer-blip floor (`ShouldSuppressAnswerBlipFlash`, 3 s) keeps an answered question's brief reply from ringing again.
- **Error:** an API-error turn (the line's `isApiErrorMessage`, never its text; checked before the stop synth, since the error line's stop reason looks terminal) → Error with the message and status on the card, until a new turn event or a rewind off the error's branch; it outranks `Done` (`SessionEnd` also fires for a fatal abort). A turn that never finished and that no process can be running → Error (`ClassifyCutOffTurn`; `SessionInfo::midTurnAtRestore`, set by every seam that applies `RestoredSessionState`, so a Deactivate or Restart mid-turn leaves Error); `SessionStart(source="resume")` keeps an Error, and `ShouldReleaseStaleError` releases one whose tail shows no error. `stopOnError` pauses that session's runner. A tool failure, a crash and Codex never read Error.
- **API-error rewind on resume** (`ApiErrorRewind.{h,cpp}`; `resumeApiErrorTurns`, default ON): one appended `last-prompt` line (`explicit:true`, never `rewound`) aimed at the user row below the failed response makes a resumed session continue the turn. ⚠ Append only after the old claude exited: a claude re-stamps its own leaf at exit, so `RewindApiErrorTail` refuses while a live heartbeat names the conversation.
- **Interrupted turns:** Restart of a session whose last turn the user interrupted asks "Continue the interrupted turn?" (Continue = the same one-line rewind + `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1`; "Keep it interrupted" is the default). A fork of a session whose turn would continue asks "Fork interrupted / uninterrupted"; interrupted arms the fork stop watch, which locks the fork's tab and presses Esc once when it starts running (`InterruptedTurns.h`, `TerminalPage.AgentTurns.cpp`). An Esc before any output writes no row: the next resume resends the prompt by itself.
- **Compaction:** `/compact` (manual or auto) runs in place (same id, same file) and writes nothing for minutes. `PreCompact` opens the compaction window (`compactingSinceUnixMs`), during which every quiescence synth stands down; `SessionStart(source="compact")` keeps a Running turn Running; `PostCompact(manual)` → WaitingForInput, `PostCompact(auto)` keeps the state; Ctx after a compaction is the boundary's `postTokens`; the live branch crosses compactions (`ActiveBranchUuids`). Only `/clear` and `/resume` switch the conversation id; a `/clear` successor is linked to its predecessor (`SessionInfo::continuedFromId`) and stays managed (`_BindClaudeSessionToTab` clears `external` and carries `started`).
- **Retired hosts:** the observations and hooks of a claude that a Deactivate or Restart closed are dropped for 10 min (`SessionRegistry::RetireHostToken`).

### The Fleet Observer

Detail: [`OBSERVER.md`](doc/agentmaster/OBSERVER.md).

- The PULL survey that detects, correlates and enriches every Claude session and tab activity out-of-band (`ProcessInspect`, `ProcessObserver`, `Activity.h`): PEB reads of each `claude.exe` (cwd, command line, env), its transcript, and claude's own presence heartbeat (`~/.claude/sessions/<pid>.json`). It only reads; it never writes to a shell (Rule #13).
- **The correlation key is the exact `WT_SESSION`** (== `ITerminalConnection::SessionId()`): each window publishes its tab roster (`PublishRoster`: `WT_SESSION`, the shell PID, bound); a claude under one of our tabs' shells is ours; the UI lane (`TerminalPage::_ObserverProbe`) binds it through `_BindClaudeSessionToTab`. A window unpublishes in `~TerminalPage`.
- **Identity:** a bare claude's conversation is the cwd's transcript created closest to (not before) its process start (Rule #14); claude's own pid-validated presence row (`PresenceRowMatchesProcess`: the exact `procStart`, else the `startedAt` window) outranks the command line's `--session-id`, because `/resume` and `/clear` switch a live claude's conversation.
- **`AM_SESSION`** (a per-process GUID; `<guid>:<windowId>` on a managed launch) classifies claudes outside the roster (ours / another Agentmaster / a real Windows Terminal / other). `ObserveClaude` enriches transient facts (pid, cwd, model, effort, branch, presence, timing), never sets `SessionState`, and none of them is persisted.
- **Adopt any `claude`:** the app's env carries `CCMGR_HOOK_PIPE` and a `claude` PATH shim (`<profile>\shim\`) that adds our `--settings`; Windows Terminal regenerates a `+` tab's env, so the roster correlation, not the shim, is the reliable bind path. An unknown session is adopted on `SessionStart` (`SessionInfo::external`) and bound by `tabToken`; a claude hosted outside this app stays observe-only (Rule #9).
- **One host tab per conversation:** when one conversation runs in several tabs, `PickConversationHost` keeps the bound tab; the others' hooks and observations are dropped (`[duplicate-host]`) and their badge reads `same conversation as another tab`.
- **The External census:** claudes and codexes Agentmaster does not manage (real Windows Terminal, consoles, sibling installs; the Claude desktop app's GUI `Claude.exe` excluded by its PE subsystem), enriched from their transcripts, shown in the board's External column and the tree's EXTERNAL scope; Adopt resumes or forks a copy into a managed tab and leaves the original running.
- **The orphan reaper** (the one place the engine ends a process): an `AM_SESSION`-stamped session whose ConPTY host died without its graceful shutdown is ended, with its whole dead console group, 5 s after it is seen (`DecideOrphanReap`; `reapOrphanedSessions`, default ON). An MCP child on its own console is never touched.
- Steady state costs microseconds: no Toolhelp snapshot while the roster and every correlated `(pid, start time)` pair are unchanged.

### Codex

- `codex.exe` is a managed agent for lifecycle and state only: no stdin injector, runner or Send-now. Every read of `~/.codex` is out-of-band; nothing is written there.
- **Facts** come from the process (`ReadCodexFacts`: model, sandbox, approval, an explicit `resume <guid>`) and its date-sharded rollout (`<CODEX_HOME|~/.codex>/sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl`, matched by cwd and start time). **State** is a rollout-tail reconciler (`ClassifyCodexLine`, `ReadCodexStateDelta`) with three states, Running / Waiting / Idle: a rollout records no approval or error.
- **Two ids:** `SessionInfo.id` is Agentmaster's handle (the registry, persistence and `_claudeTabs` key), `codexSessionId` the rollout uuid, filled on the first prompt by `_ReconcileManagedCodex`.
- Launch (the launch bar's Claude⇄Codex toggle; folders only; the launcher resolved once to a full path, `Engine::codexExePath`, a `.cmd` run through `cmd /c`), restore (`codex resume <uuid>` when the rollout exists, else fresh), window restore and adopt (`codex fork` or `codex resume`) mirror Claude's. A managed codex wears a teal `codex` pill and is deduped out of the External census.

### Prompt Queue Runner and delivery

Detail: [`DELIVERY.md`](doc/agentmaster/DELIVERY.md).

- **What it does:** each session has a prompt queue. In mode **Auto** the next Pending prompt is sent when the session is ready; in **Paused** nothing goes by itself. It runs in every build. Approvals and questions are never answered by it.
- **Names:** the UI says Prompt Queue / Prompt Queue Runner / Paused / Auto; the identifiers, persisted keys, `autorunner.log` and the CLI say autorunner / Auto Testing / `Off` / `Full` (`AutorunnerModeLabel`, `AutorunnerModeDisplayName`; a stored `SemiAuto` reads as `Off`).
- **The decision** is the pure `Scheduler::DecideAdvance` on a worker thread, triggered by a turn's `Stop` and by observed changes (an Idle session with a queue starts). It holds for: a closed or dormant tab; the **global pause** (one process-wide state, `Scheduler::SetGlobalPause`, shown on every badge as `(Off globally)`); the **question-guard** (a turn that ended in a question); the **interrupt hold** (an Esc parks an Auto runner until the user's next message); a delivery in flight; the **pickup guard** (one prompt per turn until the last one is acknowledged); and the **state settle** (40 s of steady sendable status since the later of the last status change and the queue time, `kStateSettleMs`). Backstops: `maxAutoSends`, `stopOnError`.
- **One send seam:** `SessionRegistry::SubmitPrompt` carries the auto-send, Send now and the /handover paste pump; the hosting window's submitter performs the **draft swap** (an unsent draft in the box is stashed, the prompt sent, the draft restored, each step verified by reading the box) and never types into a dormant tab.
- **The delivery gate:** one owner of a session's input box at a time (`SessionInfo::deliveryPromptId`; `TryOpen` / `CloseDeliveryGate`; 75 s expiry); its close re-fires the held advance.
- **Every paste is sanitized** with Claude Code's invisible-character rule, and every prompt compare goes through `NormalizePromptTextForCompare` (Gotcha *Claude Code cancels an Enter …*).
- **After a send:** the echo (the push hook, or the scanner's pull of the transcript line) marks it picked up. The Enter-retry watch re-presses a lone Enter up to 3 times when the turn did not start — never into a foreign draft, a menu, a dormant tab or an open gate, and verified live (`PressEnterVerified`) — then marks the prompt Failed and pauses the runner. A Sent prompt with injection evidence and no echo after 15 s at rest is judged lost (`DecideLostSend` → Failed + paused, never resent); a Sent prompt that was never injected is reclaimed to Pending.
- Mark-Sent is atomic and persisted; a restored `Sent` prompt is never replayed (Rule #4).
- **The mode is per session and persisted:** `autorunner.mode` in `sessions.json`, an interrupt hold with it. A reopened window's sessions and a Resume here keep their own mode (a queue left Paused stays Paused); a new session — a launch, a fork, a `/clear` or `/handover` successor, an adopted claude, an on-disk session resumed for the first time (`_ResumeSessionFromDisk` seeds it) — starts on the cog's default.
- ⚠ `pauseOnHumanInput` has no feeder (`SessionRegistry::NoteHumanInput` has no caller).

### Pending-input monitor (unsent drafts)

Detail: [`PENDING_INPUT.md`](doc/agentmaster/PENDING_INPUT.md).

- **Detection:** the pure `PendingInput.h` finds Claude's input box (the bottom-most `❯`+NBSP line between flush-left `─` rules) in the last ~120 rows of the active buffer, main or alt (⚠ the fullscreen renderer lives in the alt screen), read by `ControlCore::ReadPendingInputDraft` behind a mutation-id gate. `_ScanPendingInput` reads every bound, started Claude tab (background ones too), clears after two empty reads, and records `SessionInfo::pendingInput`, notifying only on the empty ↔ non-empty flip. The draft is a fact, never `SessionState`.
- **Shown** as three pulsing dots below the tab's dot and on the board card (a light / dark color pair picked by the background's luminance).
- **Kept:** in `sessions.json` (archive keeps it; a dormant tab shows the dots from memory) and in a per-session SessionStore mirror (`draft` + `draftAtUnixMs`, paste-expanded). A reopened session gets its draft typed back into its new box (`restoreDraftOnResume`, default ON; fill, never send; verified).
- **Paste placeholders** (`[Pasted text #N +M lines]`) resolve to their content from Agentmaster's paste journal (every paste it passes to a session, `NotePastedText`), then from Claude's paste cache (written by Claude only at submit; `ResolveDraftCarry`); an unresolvable placeholder is never re-typed as a label.
- **Uses:** Copy Current Prompt (the live box, else the remembered draft; placeholders copy as the pasted text); the Prompt Queue compose box pulls it in on click; the overlay's mail button moves it into the queue; the draft swap protects it around a send; a fork carries it into its new box (`carryDraftOnFork`, a piecewise fill so placeholders rebind).
- ⚠ Claude's Ctrl+S stash is not a discard (Gotcha).

### Slash-command bindings + /handover

Detail: [`COMMANDS.md`](doc/agentmaster/COMMANDS.md).

- `CommandWatch` (`AgentMaster/CommandWatch.{h,cpp}`) binds to `/commands` the user types into a managed session (seen through their transcript echo, `Kind::Command`) and awaits follow-up activity. The markdown await collects every `HANDOVER-*.md` Write / Edit after the command, seals at the first turn end (or after 20 s of write silence, held while the turn still runs), and fires once every collected file exists. Durable progress (`cmdProgress`) keeps a replayed echo from firing twice; a newer command of the same family takes over an unsatisfied older one.
- **`/handover`:** each `HANDOVER-<topic>.md` becomes the first message of its own new tab in the same effective folder, titled `<origin> (handover)`, delivered whole: on the command line when it fits `kHandoverPromptEscapedBudget`, else pasted by the pump once the tab started. **`/handover-here`** replaces the origin tab in place with the first successor. **`/handover-standby`** types each briefing into its new tab's box without sending it (verified).
- **Definition files:** Agentmaster materializes the three in `<claude-config>/commands/` (create if absent; a pristine older version upgrades by its SHA-256 digest history). ⚠ A user-edited file is never touched; ⚠ every definition keeps the `WRITE IT IN: ` marker and its phrase on one line.
- **The cog's Commands tab:** rename or disable each command (at the next start), the successor model (a leading `[model]` and `[title]` in the typed command override it), a title rewrite, the file-match regex (`HANDOVER\-`), where briefings are written (the session scratchpad by default), delete-after-hand-off (default OFF; never for the scratchpad) with its patience deadline, and the definition files' state with Reinstall. Every user regex goes through `RegexUtil.h`.

### Persistence and the session lifecycle

Detail: [`PERSISTENCE.md`](doc/agentmaster/PERSISTENCE.md), [`FAVORITES.md`](doc/agentmaster/FAVORITES.md), [`AGENT_MANAGER.md`](doc/agentmaster/AGENT_MANAGER.md).

- **Sessions:** `sessions.json` is the fleet, Open ⇄ Archived through the transient `SessionInfo::live`. Startup loads every session archived (Rule #6); a reopened window re-homes its own sessions as dormant tabs.
- **Windows:** one `WindowRecord` per window (`windows/<id>.json`: geometry, the Manager lens, ordered tab refs — Claude and Codex by session id, shell tabs as Windows Terminal startup actions — and the focused tab by identity), claimed at engine init (`Engine::ClaimWindowRecord`) and autosaved on change; the close-flush is the window's last write. `open-windows.json` holds the windows open at exit (never written empty). At start the Emperor reopens them (asking "Reopen your N previous Agentmaster windows?" when there are several); each re-homes its whole workspace (`_RestoreWindowTabs`: Claude tabs resume dormant, shells replay; Claude tabs come back before shells, so the order between the two kinds is approximate) and re-selects its focused tab. A reopened window runs no default startup tab (`_OnFirstLayout` skips `ProcessStartupActions` when `_windowRecordClaimed`): in DefaultProfile mode the reopen's `-w new -s <idx>` falls back to a default `newTab`, which would add one more shell at every reopen. **Reopen Windows (N)** reopens a closed window's record (`<alias> -w -1 -s <idx>`).
- **The restore wake:** after a restart, the restored tabs whose session was mid-turn start by themselves, one at a time across all windows, once every window's focused tab launched (`RestoreWakeBarrier`, `RestoreWakePacer`, `RestoreWake.h`).
- **Close** (the tab ✕, tree `Del`, the Manager's Close) always archives through one seam; closing the focused tab never focuses a tab that would start a process (with only such tabs left, the Agent Manager page shows).
- **Deactivate ▸** parks managed tabs: claude stops; the tab keeps its place, title, color, tags, queue and runner mode; the conversation resumes when the tab is entered or activated. Its scopes mirror Close ▸ (the folder scopes act in every window without asking), and **Deactivate All Idle Tabs** asks "This window / All windows" when other windows hold idle tabs. The park swaps a restored tab's never-initialized control into the pane (`_DeactivateManagedTab`); adopted and mid-delivery sessions are refused.
- **Restore is resume, transcript-gated:** `claude --resume <id>` only when the transcript exists, else a fresh session with the same folder and queue; a never-messaged fork re-forks from its source into the same id (`SessionInfo::forkParentId`, persisted).
- A window left with only its Manager page closes itself, unless it is the last window, and deletes its content-free record (`_CloseWindowIfManagerOnly`, race-safe through `Engine::ReserveManagerOnlyClose`).
- **Templates** save a session's queue and apply it to a session or to every session in a folder.
- **Unreadable state files** (PERSISTENCE.md §15): every loader fails open (a file it cannot read or parse loads as "nothing saved"), so a state file is never replaced without its bytes kept. `ReadStateFileUtf8` tells missing from unreadable, retries a lock and drops a BOM. The guard `PrepareStateFileReplace` (in `WriteAllUtf8` and the session store's `AtomicWriteUtf8`) refuses to replace a file it cannot read, and copies one that does not parse aside as `<name>.could-not-read-<stamp>` first. When `sessions.json` cannot be used at startup, `PreserveWorkspaceForRecovery` copies the workspace into `<profile>\recovery\<stamp>\` (with a README) before the restore changes anything.

### Identities, profiles and install

Detail: [`PROFILES.md`](doc/agentmaster/PROFILES.md).

- **Two package identities** install side by side (*Repo facts*).
- **One profile folder per install** holds all persisted state, Terminal's own settings included (`<profile>\terminal\`, the `AGENTMASTER_PROFILE` redirect in `GetBaseSettingsPath`). Resolution: env `AGENTMASTER_PROFILE` > the exe-side `profile.path` pointer > the `.portable` marker (`<exedir>\profile`) > the per-install slot in `~/.agentmaster.profiles` > the identity's default (`~/.agentmaster` for release and unpackaged, `~/.agentmaster-dev` for dev). An installed copy's first launch picks its default silently; the cog's PROFILE row changes it (at the next start). A kernel mutex warns when two instances share a folder (Rule #15).
- **A portable copy's first launch** asks where Agentmaster should live (`PortableInstall.h`, before any file is written): just for the user (`%USERPROFILE%\.agentmaster\bin`, no admin, the preferred choice), for all users (`%ProgramW6432%\Agentmaster`, one elevated step), for the signed-in user (when another account runs it), a picked folder, here, keep it portable, or ask later; the answer is the exe-side `install.path`. An install copies what the release ships (`.am-manifest`) and adds desktop and Start shortcuts, the "Open in Agentmaster" folder verbs, an Apps & Features entry and the user PATH. The app never keeps rights it was installed with.
- **A user's own install wins** over the all-users copy for that user (per-user icons through Active Setup; the shared copy hands every launch, CLI included, to the user's install, `InstallHandoff.h`; opt-out `AGENTMASTER_NO_HANDOFF=1`).
- **No install ever loses the user's state** (PROFILES.md §2b): no installer, updater or uninstaller deletes or moves a folder that is, contains or is named like Agentmaster state (`.agentmaster*`, every folder of the home map, `AGENTMASTER_PROFILE`) — every recursive delete goes through `detail::RemoveTreeGuarded` / the core's `Remove-AmTreeGuarded` — and a destination holding someone else's files is renamed aside and kept (`<folder>.before-install-<time>`), never mixed into; one holding a profile is refused. ⚠ A new delete in an install path goes through that door.
- **The downloaded copy:** once a copy installed elsewhere or handed over to an install that was there, it asks "Delete the downloaded copy?" (only for a folder of the download's files alone, `JudgeLeftoverCopy`); *Delete* moves it to the Recycle Bin after the copy's process ended (a hidden PowerShell), and only once the installed copy started.
- **A package removal keeps the package's own files; the home map is never read as "no choice" by mistake** (PROFILES.md §2d). Every Agentmaster path that removes an MSIX copies whatever its `%LOCALAPPDATA%\Packages\<family>\` storage holds into `<profile>\package-data\<family>-<time>\`, and seeds `<profile>\terminal\` from it first. That storage is normally empty; v0.1.x kept Windows Terminal's settings there. The paths: `detail::KeepPackageDataIn`, the core's `Save-AmPackageData` in `Remove-AmPackage`, the dev swap's `Save-PackageOwnFiles`. A failed copy keeps the package. `Profiles::ReadChoiceFileChecked` tells an unreadable `~\.agentmaster.profiles` from a missing one: `SaveChoiceIn` never rewrites it unread, the startup opens the default for that run only (`[profile]` line), and the zip install refuses rather than guess (`TryUserInstallProfileDir`). ⚠ A new `Remove-AppxPackage` goes through `Remove-AmPackage`, or keeps the files itself.
- **Uninstall** (`--uninstall-portable`: Apps & Features, the cog) acts on what the folder is; profiles always stay.
- `tools\Install-Agentmaster.ps1` and the embedded `am-update.ps1` share one byte-identical install core: ⚠ edit it in both (`tools\tests\Test-AgentmasterInstaller.ps1` checks), keep both pure ASCII, elevate with `Invoke-AmElevatedPowerShell` (never `Start-Process -Verb RunAs`), and never name a local `$version` in a function with a `-Version` parameter.

### In-app auto-updater

Detail: [`UPDATER.md`](doc/agentmaster/UPDATER.md).

- `Updater.h` checks GitHub releases at startup (bounded, before the reopen prompt) and every hour (a `WM_TIMER` on the Emperor's window; the prompt runs on a detached thread), for the release package and portable copies.
- **The prompt:** Update now / Postpone, with six postpone choices (next restart — the default — · tomorrow 08:00 · 3 · 7 · 30 days · skip this version). Update now writes and runs the built-in `am-update.cmd` + `am-update.ps1` (the package: certificate + `Add-AppxPackage`; a portable copy: an in-place zip swap keeping `settings\`, `profile\`, `profile.path`, `install.path`), then quits.
- **Channels:** stable always; pre-releases with `allowUpdatePrerelease`; nightlies (a tag containing `nightly`) only with `allowUpdateNightly`, behind a warning.
- ⚠ Every entry point is no-throw with a safe default; asset URLs must be `https://github.com/<repo>/releases/download/…` (`IsTrustedAssetUrl`); every catch logs `[update]`.

### The agentmaster CLI

Detail: [`CLI.md`](doc/agentmaster/CLI.md).

- `agentmaster <verb>`: `show <ref>`, `list`, `sessions` (open only by default; `--archived`, `--state`, `--dir`), `tabs`, `windows`, `external`, `--self`, `--json` (schema 2), `--tail N`, `--profile` / `--instance`. Exit codes: 0 · 1 (not found, ambiguous, `--self` found nothing) · 2 (usage). It works with the app up or down, reading only persisted and OS-observable state (`AgentMaster/cli/agentcli.cpp`); state is derived from the presence heartbeat and the transcript tail.

- **Every dialog is echoed** to the console of the command that started the process (`CallerSink.h`, `DialogEcho.h`). ⚠ Never call `MessageBoxW` / `TaskDialog*` / `IFileDialog::Show` directly: use DialogEcho's wrappers (`TestDialogEchoCoverage` fails on a direct call).

### PRESETS

Detail: [`HARNESSES.md`](doc/agentmaster/HARNESSES.md).

- Named launch presets put a session on another model or provider (OpenRouter, Xiaomi MiMo, NanoGPT, a RunPod vLLM endpoint, or any Anthropic-compatible endpoint): an `@<id>` target listed after a separator in every Open New Session Here / Fork session menu and the Launch button's hover menu. The list starts empty ("Add presets…" points to Settings ▸ Presets ▸ TEMPLATES).

## Building FAST

- This machine: **i9-13900K — 32 threads (8 P + 16 E cores), 64 GB RAM.**
- The stock `Invoke-OpenConsoleBuild` is slow: msbuild without `/m` (projects build serially), the whole solution (tests, tools, samples) and a `nuget restore` on every call. Per-file `/MP` is on (`src/common.build.pre.props`).

> ⚠️ **Hold the `build-launch` mutex before any full exe build, launch, or deploy** (*Deploy & run →
> Concurrency lock*). A lib-only compile check (#6) does not relink the running exe and needs no lock.

> 🚀 **Skip the `.appxsym` symbol package.** `GenerateAppxSymbolPackage` zips every Debug PDB into a
> Store symbol bundle nothing uses (~156 s of a ~204 s build); the PDBs still sit beside the binaries.
> `Build-Agentmaster.ps1` passes `/p:AppxSymbolPackageEnabled=false` by default (`-WithSymbolPackage`
> turns it on); a raw `msbuild` must add the flag itself.

1. **Every build writes to Q:, never to K:.** `K:` is a nearly full, DRAM-less SATA SSD; `Q:` a Gen4 NVMe with ~250 GB free; only the source tree stays on K:.
   - **Package layouts** go to `Q:\agentmaster-layouts\<Release | Release-B | Debug | Debug-B>` through `-LayoutDir`: the slot the instance does NOT run from (*Hot deploy*).
   - **The build trees are junctions to Q:**, so every build writes there, with or without `-LayoutDir`: `obj\x64\Debug` → `Q:\tmp\agentmaster-dev-build`, `obj\x64\Release` → `Q:\tmp\agentmaster-release-build`, `bin` → `Q:\tmp\agentmaster-bin`, `src\cascadia\CascadiaPackage\bin` → `Q:\tmp\agentmaster-package-bin`, `…\CascadiaPackage\obj` → `Q:\tmp\agentmaster-package-obj`, `…\CascadiaPackage\AppPackages` → `Q:\tmp\agentmaster-apppackages`.
   - **On K: by design:** the source tree's `Generated Files` folders (shared by both configurations, deleted by purges), `packages\` (the NuGet input) and `obj\x64\vcpkg` (the installed vcpkg packages).
   - **Before a build**, check the junctions (`cmd /c dir /AL K:\source\Agentmaster`, `…\obj\x64`, `…\src\cascadia\CascadiaPackage`). Recreate a missing one with `New-Item -ItemType Junction -Path <K: path> -Target <Q: folder>`, after moving to Q: anything a build wrote at the K: path; remove a junction only with `cmd /c rmdir <path>` (it deletes the link, never the target). A new build folder gets its Q: folder and its junction before its first build.
2. **Use the wrapper** — parallel `/m` + per-file `/MP`, scoped to the app target (`Terminal\CascadiaPackage`):
   ```powershell
   pwsh -ExecutionPolicy Bypass -File .\tools\Build-Agentmaster.ps1            # first build
   pwsh -ExecutionPolicy Bypass -File .\tools\Build-Agentmaster.ps1 -NoRestore # inner loop
   ```
   Raw equivalent: `msbuild OpenConsole.slnx /m /p:Configuration=Debug /p:Platform=x64 /p:AppxSymbolPackageEnabled=false /t:Terminal\CascadiaPackage /v:m`. Under memory pressure cap `-MaxCpu` and `-ClMpCount`.
3. **Windows Defender exclusions** (Admin, once — 20–40% on cold builds):
   ```powershell
   Add-MpPreference -ExclusionPath (Resolve-Path .)
   'MSBuild.exe','cl.exe','link.exe','cppwinrt.exe','midl.exe','mc.exe','VBCSCompiler.exe','nuget.exe','tracker.exe' |
     ForEach-Object { Add-MpPreference -ExclusionProcess $_ }
   ```
4. **Iterate incrementally.** The cold build (restore + cppwinrt projection) is the expensive one; a `-NoRestore` rebuild of a few TUs takes ~20–50 s, and a hot engine header (one included by dozens of TUs) recompiles all of them.
5. **Purge triggers:** a change to `SessionModels.h`, `SessionRegistry.*` or an `.idl` needs a purged, full rebuild (the `build-install` skill §5.8). A change to the data members of `TerminalPage`, `Engine`, `MessagingService`, `Scheduler` or another struct shared across TUs (`WindowTabTools.h`'s `WindowTabInfo`) is not on the automatic list: force the purge, or the build runs a stale class layout.
6. **Compile-check without relinking the exe.** `TerminalAppLib` is a static lib, so the lib alone validates code while the app runs (after `vcvars64.bat`):
   ```
   msbuild src\cascadia\TerminalApp\TerminalAppLib.vcxproj /m /p:Configuration=Debug /p:Platform=x64 /p:SolutionDir=K:\source\Agentmaster\
   ```
   `/p:SolutionDir=` (with its trailing `\`) is required for a direct `.vcxproj` build (else MSB4019); the full exe link is `msbuild OpenConsole.slnx /m /p:Configuration=Debug /p:Platform=x64 /p:AppxSymbolPackageEnabled=false /t:Terminal\CascadiaPackage`.

- Optional: MSBuildCache (`-p:MsBuildCacheEnabled=true`) for cache hits on clean rebuilds and branch switches.

## The build server (`amb`)

Detail: [`buildserver/README.md`](buildserver/README.md); the design, the plan and every measurement: [`buildserver/DESIGN.md`](buildserver/DESIGN.md).

- **What it is:** a service on this PC that builds Agentmaster in a Windows VM and runs e2e suites on builds in fresh VMs, with everything on Q:: its site is the WSL distro `buildserver` (disk `Q:\buildserver\wsl\ext4.vhdx`), its VMs are dockur slots there, its coordinator is `amb-coordinator`. A build gets a build id (`b<yyyyMMdd>-<n>`) whose files stay in the site's store.
- **`amb`** is `Q:\tmp\buildserver-build\Amb.Cli\bin\Debug\net10.0-windows\win-x64\amb.exe` (`dotnet build buildserver\src\Buildserver.slnx`). The coordinator exits after 10 idle minutes; `amb` starts it again.
- **Build:** `amb build [<rev>] [--config Release|Debug] [--identity dev|release] [--purge none|force] --wait`. `<rev>` (default HEAD) is resolved in `K:\source\Agentmaster` and the COMMIT is built, never the working tree: commit first. ⚠ It is a build: ask the user first (*Development Rules*). One build at a time in the kept build VM `build-1`, whose worktrees on its data disk (one per configuration × identity) make the next build incremental: a worktree's first build is cold (Release ~43 min from request to build id, Debug ~24 min), a later one 10–12 min. An identical request (commit, configuration, identity, purge) returns the existing build id. Each build id keeps ~0.6 GB in the store, and nothing deletes builds yet. ⚠ A Debug build's binaries need the Windows SDK's `ucrtbased.dll`: e2e takes Release builds.
- **Use a build:** `amb e2e <build id> [--wait] -- -v suites/test_smoke.py` (a suite in a fresh `am-e2e` VM; nothing is left behind); `amb artifacts <build id>`; `amb fetch <build id> [--kind portable-zip|layout-zip|symbols-zip|build-log|build-json|all]` copies into `Q:\buildserver\out\<build id>` (refused on K:), checking each SHA-256. **Install a build** on this PC: `amb fetch <build id> --kind layout-zip`; extract the zip (the layout's files are at its root) into the EMPTY `Q:\agentmaster-layouts` folder of the instance's pair that it does not run from; check that its `AppxManifest.xml` names the instance's package at 0.0.1.0 and that `TerminalApp.dll` bakes the build's commit; then the swap script (*The swap script*). A Debug layout from the VM holds the same files as a local one, and this PC has the debug UCRT it needs.
- **Watch and stop:** `amb status` (Windows' numbers, homepc's free share, the requests and slots), `amb list`, `amb logs <id> -f`, `amb cancel <id>`. A request waits while homepc has too little free (`waiting: homepc: memory`; a build needs 8 GB beyond Windows' 6 GB), up to its wait timeout.
- **Operate the site:** `python buildserver/site/sitectl.py deploy | up | down | status` (`down` cancels running requests: `amb status` first); the images: `python buildserver/image/images.py build-image | e2e | check | list`. ⚠ Never `wsl --shutdown`, and `sitectl.py provision` restarts the distro (it ends every slot).

## Deploy & run

- A packaged app runs as a registered package (a loose layout or an installed MSIX), never by starting `Agentmaster.exe` directly (WT #926/#4043).
- **Launch** dev by its alias **`agentmasterdev`**, the Start menu's **"Agentmaster Dev"**, or `Start-Process "shell:appsFolder\AgentmasterDev_56k4f06dsfp9r!App"`; production by `agentmaster`, "Agentmaster" or `shell:appsFolder\Agentmaster_56k4f06dsfp9r!App`.
- A new build goes in through the swap (*The swap script*), which also registers a changed manifest: a build's manifest says `0.0.1.0`, and a re-registration accepts only a newer version.
- A dev install's state is its profile (default `%USERPROFILE%\.agentmaster-dev\`, or the folder named in `%USERPROFILE%\.agentmaster.profiles`); its `hooks.log` shows the engine (`[engine] bridge listening …`) and the hooks arriving (`[SessionStart]`, `[Stop]`, …).

### Concurrency lock (multi-agent) — REQUIRED before any build, launch, or deploy

- There is one dev instance and one build tree (`bin` + `obj`, junctions to Q:), so the close → build → relaunch cycle is process-global and destructive: two actors (two agents, or an agent and a human) close each other's instance, race msbuild on the same outputs, and fail the exe link, because a running `Agentmaster.exe` locks the exe being relinked.
- **Hold the global `build-launch` mutex for the WHOLE cycle before you build (full exe), launch, deploy, or close our instance.** A lib-only compile check (*Building FAST* #6) needs no lock. The mutex is a filesystem lock (`tools/am-lock.sh`, `mkdir` atomicity) under `%USERPROFILE%\.agentmaster\locks\`, so it persists across Bash calls and every agent shares it.

```bash
TOKEN=$(bash tools/am-lock.sh acquire --wait 600 --label "deploy $(git rev-parse --short HEAD)") || exit 1
# ... entire close → build → relaunch cycle while holding $TOKEN ...
bash tools/am-lock.sh release --token "$TOKEN"
```

- `acquire` prints the token on stdout (capture it) and logs to stderr; `--wait 600` queues behind another holder (picking up within ~1 s of its release). Without `--wait`, a contended `acquire` exits **3 (`BUSY`)** and prints the holder: back off, don't spin.
- A lock past its TTL (30 min) is broken by the next `acquire`; `release` is token-checked. Helpers: `status`, `refresh --token T` (extend a long hold), `acquire --force`, `with --wait 600 -- <cmd>`; `bash tools/am-lock.sh --help`.

### Inner loop (close, build, relaunch)

- The loose layout is live, but `Agentmaster.exe` cannot be relinked while the app runs. Ask the user first (*Development Rules*), hold the lock, and never touch the Store Windows Terminal (it is not under our path). The hot deploy below avoids the close.
- ⚠ **Dev runs from one of two layout slots** (`Q:\agentmaster-layouts\Debug` or `Debug-B`): read the registered folder first and close and build that one; a hard-coded folder does nothing while dev runs from the other.

```bash
# 0. acquire the global mutex — REQUIRED (queues behind another agent's build)
TOKEN=$(bash tools/am-lock.sh acquire --wait 600 --label "deploy $(git rev-parse --short HEAD)") || exit 1
```

```powershell
# 0b. the folder dev is REGISTERED from: Q:\agentmaster-layouts\Debug or Debug-B
$devDir = (Get-AppxPackage AgentmasterDev).InstallLocation.TrimEnd('\')
# 1. stop ONLY our dev instance's GUI process (the path filter spares the Store WT and the release
#    layout, which may host your own session). ⚠ NEVER Stop-Process OpenConsole.exe: a ConPTY host
#    killed outright skips its CTRL_CLOSE broadcast, and its tab's pwsh + claude.exe (+ MCP children)
#    live on with a dead console (OBSERVER.md §13a). Stopping the GUI closes its pipe handles; every
#    OpenConsole then ends its clients and exits. The trailing '\*' keeps ...\Debug from matching
#    ...\Debug-B.
Get-CimInstance Win32_Process -Filter "Name='Agentmaster.exe' OR Name='WindowsTerminal.exe'" |
  ? { $_.ExecutablePath -like "$devDir\*" } | % { Stop-Process -Id $_.ProcessId -Force }
# 1b. wait for the layout's ConPTY hosts to drain before relinking (they lock OpenConsole.exe; each ends
#     its clients, ≤ 5 s per stubborn client; a host still alive after ~30 s is wedged)
$deadline = (Get-Date).AddSeconds(30)
do { Start-Sleep -Milliseconds 500; $hosts = Get-CimInstance Win32_Process -Filter "Name='OpenConsole.exe'" |
  ? { $_.ExecutablePath -like "$devDir\*" } } while ($hosts -and (Get-Date) -lt $deadline)
# 2. build INTO the registered folder (-LayoutDir; without it the layout lands in the wapproj's default
#    folder and dev never sees the new binaries)
pwsh -File .\tools\Build-Agentmaster.ps1 -NoRestore -LayoutDir $devDir
# 3. relaunch
Start-Process "shell:appsFolder\AgentmasterDev_56k4f06dsfp9r!App"
```

```bash
# 4. release the mutex (always — even if a step above failed)
bash tools/am-lock.sh release --token "$TOKEN"
```

### Hot deploy (build while it runs)

- Each instance alternates between two layout slots on Q:: dev `Q:\agentmaster-layouts\Debug` / `Debug-B`, production `Release` / `Release-B` (a layout may live in any folder). Read `(Get-AppxPackage <name>).InstallLocation`, build into the slot the instance does NOT run from, then swap; the slot it left keeps the previous build, the rollback target.
  - **Production:** `tools\Build-Agentmaster.ps1 -NoRestore -Configuration Release -ReleaseIdentity -LayoutDir <slot>`, then `tools\Swap-AgentmasterLayout.ps1 -LayoutDir <slot>`.
  - **Dev:** `tools\Build-Agentmaster.ps1 -NoRestore -LayoutDir <slot>`, then `tools\Swap-AgentmasterLayout.ps1 -LayoutDir <slot> -PackageName AgentmasterDev` (it refuses a release-identity layout).
- A running instance locks only its own layout (loaded images, the mapped `resources.pri`), never the `bin` / `obj` trees, so the build needs no close (`-LayoutDir` → `/p:AgentmasterLayoutDir`, which `CascadiaPackage.wapproj` turns into DesktopBridge's `OutputPath` before its props import). The icons follow the slot (`CopyAgentmasterImagesToLayout` → `$(TargetDir)Images\`): a layout without them registers with blank taskbar and Start icons, and the swap refuses it.
- **An installed MSIX** (a release's package, `IsDevelopmentMode` False; the *Builds* table says which install runs one). Windows registers no loose layout over an installed package of the same family (`0x80073CFB`, AppXDeployment-Server event 409), nor the reverse; `Get-AppxPackage` tells them apart (installed: `SignatureKind Developer`, `IsDevelopmentMode False`; loose: `None`, `True`). The swap refuses an installed package in step 1 unless `-ReplaceInstalledPackage -RollbackBundle <the installed version's .msixbundle>` is given: it then removes the package between the drain and the register (per user, no administrator rights; the app's state lives in the profile) and reinstalls the bundle on any failure. `tools\Install-Agentmaster.ps1` leaves the bundle it installed in `%TEMP%\Agentmaster-install\Agentmaster_<version>.msixbundle` (signed by `CN=Agentmaster`, whose certificate it put in TrustedPeople). Pins to Start or the taskbar may need making again. The way back to a release: remove the loose registration, then install the bundle (`Install-Agentmaster.ps1` does both; it and `am-update.ps1` answer `0x80073CFB` that way).
- Hold the `build-launch` mutex across build and swap, and refresh it during a long build. Runbook: the `build-install` skill §4a.

### The swap script — `tools\Swap-AgentmasterLayout.ps1`

- **What it does:** it moves an installed loose registration (`Agentmaster` or `AgentmasterDev`) to a freshly built layout folder, with seconds of downtime; with `-ReplaceInstalledPackage` it also moves an INSTALLED package (a release's MSIX) to a loose layout, removing the package between the drain and the register. It is the swap half of a hot deploy; the build half is `tools\Build-Agentmaster.ps1 -LayoutDir <slot>`.
- **What it does not do:** it builds nothing, and it takes no lock: hold the `build-launch` mutex around the build AND the swap yourself.
- **Run it with PowerShell 7** (`pwsh`; `#Requires -Version 7`), from a shell OUTSIDE the instance that it swaps.
- **The reference** is the script's comment-based help; `Get-Help` does not show it, so read the script header.

#### The six steps

Nothing stops before step 3, so a refusal in step 1 costs nothing.

1. **Validate.** The script refuses (it throws; exit code 1 when run as a script) when:
   - `-LayoutDir` has no `AppxManifest.xml`, or the manifest does not parse.
   - The manifest's Identity Name is not `-PackageName`, so a dev layout never replaces the release family, and the reverse.
   - An image that the manifest names (`Images\X.png`) is missing, both as that file and as every MakePri variant (`X.*.png`).
   - `-LayoutDir` is the folder that the package already runs from.
   - The version is not newer than the registered one, or the revision would pass 65535.
   - The calling shell descends from a GUI process that the swap stops (the self-hosting guard; it runs under `-WhatIf` too): the stop would kill the script after step 3 and leave the package stopped and unregistered.
   - The registered package is an INSTALLED one (`IsDevelopmentMode` False) and `-ReplaceInstalledPackage` is not given; or it is given and `-RollbackBundle` is missing, is not validly signed by a trusted signer, or names another package or version than the installed one.
2. **Stamp.** It writes the new version into the layout's manifest. A build always writes `0.0.1.0`, and development-mode re-registration accepts only a newer version.
3. **Stop.** It stops only the GUI processes under the old folder, their image names read from the OLD layout's manifest (fallback: `Agentmaster.exe`, `WindowsTerminal.exe`). It never stops `OpenConsole.exe`.
4. **Drain.** It waits for the old folder's ConPTY hosts to exit by themselves (each first ends its tab's shell and claude with `CTRL_CLOSE`); the register cannot succeed while one lives, and a workspace with many live tabs drains slowly (~90 s for 72 hosts). A failed process census (a WMI "Call cancelled") is taken again a second later and never ends the script.
   - **4b. Remove**, only with `-ReplaceInstalledPackage` and an installed package: hosts left after the drain get up to `-RegisterRetrySec` more (the removal would end them without their `CTRL_CLOSE`). Any file in the package's own storage is copied into its profile's `package-data\` first (`Save-PackageOwnFiles`; a failure rolls back with the package still installed). Then `Remove-AppxPackage <full name>` runs, retried on `0x80073D02`, and so does any bundle entry still registered under the name.
5. **Register.** `Add-AppxPackage -Register <manifest> -ForceUpdateFromAnyVersion` moves the InstallLocation to the new folder; on `0x80073D02` (the old package still in use) it tries again every 3 s.
6. **Launch.** It starts `shell:appsFolder\<PFN>!<AppId>` and waits for the new GUI process under the new folder.

#### Parameters

| Parameter | Default | Effect |
|---|---|---|
| `-LayoutDir <folder>` | (required) | The built layout folder to switch to. A relative path resolves against the PowerShell location. |
| `-PackageName` | `Agentmaster` | `Agentmaster` (release) or `AgentmasterDev` (dev). It must be the layout manifest's Identity Name. |
| `-Version <a.b.c.d>` | the registered version, revision + 1 | The version to stamp and register; it must be newer than the registered one. Keep `Major.Minor.Build`: the in-app updater compares those three parts with the GitHub releases. |
| `-DrainTimeoutSec` | 120 (0–600) | How long to wait for the old hosts. They are never killed (a killed host skips its `CTRL_CLOSE`, OBSERVER.md §13a); the register's retries cover hosts still alive. |
| `-RegisterRetrySec` | 120 (0–600) | How long to retry the register on `0x80073D02`, counted from the first attempt. `0` disables the retry; any other register error rolls back at once. |
| `-LaunchTimeoutSec` | 60 (1–600) | How long to wait for the new GUI process. It affects only the report: the app starts either way. |
| `-NoLaunch` | off | Register, but do not start the app; a rollback then starts nothing either (a reinstall of `-RollbackBundle` still runs). |
| `-ReplaceInstalledPackage` | off | Allow the swap over an INSTALLED package: step 4b removes it between the drain and the register. Ignored, with a note, for a loose registration. |
| `-RollbackBundle <file>` | (none) | Required with `-ReplaceInstalledPackage` over an installed package: the `.msixbundle` / `.msix` of the INSTALLED version, checked in step 1 (exists, signature `Valid`, same package and version). The only way back once the package is removed: any failure after the removal reinstalls and starts it. |
| `-WhatIf` | off | Dry run: resolve, validate (the icons, the self-hosting guard and the installed-package checks included) and print the plan. It stamps, stops, removes and registers nothing. |

#### Output, failure and undo

- **Progress:** one `[HH:mm:ss.fff]` line per step: `package`, `target`, [`remove … the way back is …`,] `running`, `stopped`, `drained`, [`removed … in Xs`,] `register attempt N … retrying`, `registered`, `launched pid N - downtime Xs`. On a failure: `REMOVE FAILED: …` / `REGISTER FAILED: …`, then `rollback: …` lines, or `ROLLBACK FAILED: …` with the commands to run by hand.
- **Result object** (printed last): `Package`, `OldVersion`, `OldLocation`, `NewVersion`, `NewLocation`, `StoppedPids`, `DrainSeconds`, `HostsLeft` (old hosts alive when the drain ended), `RegisterSeconds` (retries included), `RegisterAttempts`, `NewPid` (0 = not started, or not seen within `-LaunchTimeoutSec`), `DowntimeSeconds` (from the GUI stop to the new GUI's kernel start time; empty when unknown), `RemovedPackage` / `RemoveSeconds` (step 4b; empty / 0 without it).
- **Rollback:** the script never changes the old folder. When anything fails between the stop and the end of the register (the drain, step 4b's removal, the register after its retries), it brings the old version back (unless `-NoLaunch`) and then throws the original error: it relaunches the still-registered old version, or, once step 4b removed the package, reinstalls `-RollbackBundle` and starts it. Every census tolerates a failed query (`Get-ProcessUnderOrNull`), and one `catch` around steps 4–5 runs the rollback (`Invoke-SwapRollback`, at most once). Only a failed reinstall leaves the app uninstalled: the `ROLLBACK FAILED` line then names `Add-AppxPackage -Path <bundle>` and the start command.
- **A transcript with a `stopped` line but neither `registered` nor `rollback:`** means the instance is DOWN (a killed script, or an older copy of it): start it yourself (`Start-Process "shell:appsFolder\<PFN>!App"`); the old registration is still in place.
- **Undo** a successful swap: run the script again with `-LayoutDir` set to the previous slot (that folder gets the next version number, like any swap).

#### What a swap ends, and who can run it

- **The stop ends every claude of that instance:** each host sends `CTRL_CLOSE` to its tab, the window restore re-homes the tabs, and each Claude tab resumes its conversation (dormant until focused); a turn in flight is cut off. Before a swap make sure no session is Running: `agentmaster sessions` (production) or `agentmaster sessions --instance dev`, reading the state (`derivedState` in `--json`), not `turnInFlight` (that flag reads only the transcript tail and is true on some sessions whose heartbeat reads idle).
- **Walk your shell's ancestry before a swap.** A session inside production cannot run the release swap, and a session inside dev cannot run the dev swap (the self-hosting guard refuses). Run the other instance's swap yourself, and give the user the command for your own host's swap, to run from Windows Terminal, the other instance or a plain console.
- **When the user tells you to swap your own host anyway, start the swap through a one-shot scheduled task** (`Register-ScheduledTask` with `-LogonType Interactive -RunLevel Limited`, then `Start-ScheduledTask`; the script deletes its task as its first step). The Task Scheduler service becomes the script's parent, so the guard passes, the stop cannot kill it, and it runs on the user's desktop, where it can relaunch the app. A plain `Start-Process` does not work: the child descends from the session that the stop ends and shares its job object. The script must wait until your own turn has ended (no session `Running`, by `derivedState`) before it stops the GUI, because your session ends with the stop.
- **The same task can run the build too**, so no step depends on your session: build, check the layout, release the mutex, wait for the starting session's turn to end, take the mutex again, swap. A task starts from the registry environment, not from an Agentmaster tab, so it gets no PATH compaction: shorten a PATH over 7,167 characters before the build (vcvars runs through cmd.exe; Gotcha *PATH*), and call Git Bash by its full path for `am-lock.sh` (a bare `bash` can resolve to WSL's).

#### Traps

- **Never register a fresh build by hand.** Its manifest says `0.0.1.0`. Swap it.
- **Read `(Get-AppxPackage <name>).IsDevelopmentMode` before a swap.** `False` is an installed package (a release's MSIX), which only `-ReplaceInstalledPackage -RollbackBundle <bundle>` can replace (*Hot deploy*).
- **`-WhatIf` noise:** it prints a `What if: Performing the operation "Set Alias"` line for each alias; filter them out.
- **The new instance can stop on the "Reopen your N previous Agentmaster windows?" dialog.** The measured downtime ends when the new GUI starts, not when someone answers; someone must click it.
- **After a swap, the instance runs from the OTHER slot.** The next build targets the slot that it left.

#### The build half, and both instances in one deploy

- **`Build-Agentmaster.ps1 -LayoutDir <folder>`** writes only the package layout to that folder (`/p:AgentmasterLayoutDir`); every other project keeps its usual `bin\` and `obj\`; it registers nothing. The switches that matter for a swap build:
  - `-NoRestore` (the packages exist already);
  - `-Configuration Release -ReleaseIdentity` for production (without `-ReleaseIdentity` the layout is `AgentmasterDev`, which the swap refuses for `Agentmaster`);
  - `-MaxCpu N` / `-ClMpCount N` to cap the parallel work under memory pressure (`4` / `6` with ~80 live claudes);
  - `-WithSymbolPackage` only when a Store symbol bundle is needed.
- **To deploy both instances** ("build release and debug for swap"):
  1. Walk your shell's ancestry, and acquire the mutex.
  2. Read both InstallLocations. Each build targets the slot its instance does NOT run from.
  3. Apply the purge rule (the `build-install` skill §5.8) to each configuration; its baseline is the time of `bin\x64\<Config>\TerminalApp\TerminalApp.dll`, the last build of that configuration.
  4. Build Release (`-Configuration Release -ReleaseIdentity -LayoutDir <release slot>`), THEN Debug (`-LayoutDir <dev slot>`). Never run the two builds at once: both write the same `src\cascadia\TerminalApp\Generated Files` folder, and two builds double the memory load.
  5. Swap each instance from a shell outside it (`-PackageName AgentmasterDev` for dev), then release the mutex.

## Releasing a public version

### Only when the user agrees / requests it.

- Cutting a release builds, self-signs and publishes a GitHub Release. It is outward-facing: confirm the **version** with the user first, and never cut one on your own initiative. Local deploys follow *Deploy & run*.
- Two GitHub Actions workflows are the repo's only CI (Windows Terminal's Azure / OneBranch pipelines under `build/pipelines/` never run for this fork):
  - **`.github/workflows/ci.yml`:** a build-only gate on `pull_request` and pushes to `agentmaster` / `main` (+ `workflow_dispatch`): restores vcpkg + nuget (cached), builds `Terminal\CascadiaPackage` x64 Release, and builds and checks the release symbols exactly as `release.yml` does (nothing is uploaded). No path filter: a docs-only push still runs a ~20-min build (add `paths-ignore: ['**.md','doc/**','LICENSE']` if that matters).
  - **`.github/workflows/release.yml`:** the public-release pipeline, triggered by a tag `v*` or `workflow_dispatch` (a `version` input); no cron, no Azure, no NuGet publish (NuGet restore stays: it is a build dependency).

### To cut a release (happy path):

```bash
# agree X.Y.Z with the user, then either tag-push (real release) ...
git tag vX.Y.Z && git push origin vX.Y.Z          # auto-triggers release.yml
# ... or dispatch a DRAFT dry-run without creating a tag:
gh workflow run release.yml --repo Nucs/Agentmaster -f version=X.Y.Z
# find + watch the run (background it; it pings on exit; --exit-status => failure is non-zero):
gh run list --repo Nucs/Agentmaster --workflow release.yml --limit 3
gh run watch <run-id> --repo Nucs/Agentmaster --exit-status
```

- **The pipeline:** prep (the version from the tag or input, stamped into `Package-Rel.appxmanifest`'s `Identity Version`) → build, a matrix of x64 + arm64 (Release, `WindowsTerminalBranding=Dev`, `/p:AgentmasterPackageIdentity=Release`, `AppxPackageSigningEnabled=false`) → bundle (`build/scripts/Create-AppxBundle.ps1` merges both arches into an `.msixbundle` and self-signs; `New-UnpackagedTerminalDistribution.ps1 -PortableMode:$true` makes the portable zips, whose first launch asks where Agentmaster should live, PROFILES.md §2b) → release (`softprops/action-gh-release` creates a **draft** with the `.msixbundle`, `Agentmaster.cer`, both portable `.zip`s with public PDBs, and both `_symbols.zip`s with the full PDBs).
- The user reviews and publishes the draft (a draft creates no tag until published; a `workflow_dispatch` draft is safe to delete); afterwards refresh the release notes and the README (capabilities, Download) when the features moved.
- **Nightlies:** a tag containing `nightly` (`vX.Y.Z-prerelease-nightly`; bump `X.Y.Z`, the updater compares numerically): prep strips each version component to digits for the MSIX `Identity Version` while the tag, release name and installer keep the full suffix; the release is marked prerelease with a nightly warning; the updater offers it only to users who opted in, and `Install-Agentmaster.ps1` mirrors the tiers (`-Nightly`; `-Prerelease` alone never installs a nightly).
- **Symbols** ([`SYMBOLS.md`](doc/agentmaster/SYMBOLS.md)): every release ships the PDB of every binary it builds: public PDBs (`/PDBSTRIPPED`, listed in `.am-manifest`) beside the binaries in the portable zips, and the full PDBs (Source-Linked through `tools/New-AgentmasterSourceLink.ps1`, srcsrv-indexed by `build/scripts/Index-Pdbs.ps1`) in `Agentmaster_<ver4>_<arch>_symbols.zip`. `tools/Export-AgentmasterSymbols.ps1` matches each binary to its PDB by GUID + age and fails the run on a missing, stale or unindexed one. The build passes `/p:AgentmasterSourceLinkFile` + `/p:AgentmasterPublicPdbDir` (read only by `src/common.build.post.props`) and `/p:AppxSymbolPackageEnabled=false`; the msixbundle carries no PDBs.

### Signing.

- The release self-signs with a **`CN=Agentmaster`** code-signing certificate minted at run time, its subject read from the manifest, so it always equals the Publisher.
- Users trust `Agentmaster.cer` once to install the `.msixbundle`; the **portable `.zip` needs no certificate** (unzip, run `Agentmaster.exe`).
- To sign with a real certificate, set the repo secrets **`SIGNING_PFX_BASE64`** + **`SIGNING_PFX_PASSWORD`** (its subject must still equal the Publisher).

### One-time repo settings

- A fork needs Actions enabled (off by default on forks) and workflow write permission (the release job creates the Release); both are set for `Nucs/Agentmaster`:

```bash
gh api -X PUT repos/<owner>/<repo>/actions/permissions -F enabled=true -f allowed_actions=all
gh api -X PUT repos/<owner>/<repo>/actions/permissions/workflow -f default_workflow_permissions=write
```

- The workflows run on a stock `windows-2022` runner (UWP workload, Windows SDK and vcpkg present) and build x64 + arm64 in parallel; a failed build uploads its binlog as an artifact.

## Gotchas (learned the hard way)

### Build and C++

- **`nuget.exe` can't parse `.slnx`:** the bundled `dep\nuget\nuget.exe` errors "file type was not recognized" on `OpenConsole.slnx`, and a bare `packages.config` restore needs `-PackagesDirectory`. The wrapper restores `dep\nuget\packages.config` into `packages\` (non-fatal); use `-NoRestore` once packages exist.
- **A `.vcxproj` built directly needs `/p:SolutionDir=K:\source\Agentmaster\`** (trailing `\`), else the `$(SolutionDir)build\rules\*.targets` imports fail (MSB4019); the `.slnx` build sets it.
- **`small` is a macro under `<windows.h>`** (`rpcndr.h`: `#define small char`), and so are `hyper`, `near`, `far` and `interface`: never use them as identifiers (`const PixelSize small{…}` fails with C2628 / C2144 / C2059 cascades pointing nowhere near a macro).
- **A two-parameter static `Set<X>(a, b)` on a XAML runtime class** (`TermControl`, any control) is read by the XAML compiler as an attached property's setter; with a non-element first parameter, `XamlTypeInfo.g.cpp` fails to compile (C3083 'System', C2039 'Void', C2737) in the project that owns the type. Name such a static `Configure<X>` / `Apply<X>`; a C++-only static outside the `.winmd` is safe.
- **`Grid` / `Panel` have no `Focus(FocusState)`** in this projection (C2039): focus a `Control` child (`IPaneContent::Focus`; `AgentManagerContent::Focus` focuses its cwd `TextBox`).
- **`TextBox` has no `VerticalScrollBarVisibility`:** use the attached `ScrollViewer::SetVerticalScrollBarVisibility(box, …)`. Render a compose bar's symbols as `FontIcon` (a `TextBlock` reserves descent space and a centered `"!"` sits high).
- **Imperative XAML name clashes:** `using namespace winrt::Windows::UI;` pulls the nested `Text` namespace in and collides with a `Text(...)` helper (C2872 / C2882): use narrow using-declarations (`Color`, `ColorHelper`, `Colors`). Inside a `TerminalPage` member, a bare `FontFamily{…}` is the page's own property (C3321): write `winrt::Windows::UI::Xaml::Media::FontFamily{…}`.
- **Erasing a map node invalidates references to its key:** copy the key first (`const std::wstring superseded = oldId;`). A `[key, val]` binding's reference used after `erase` hashes freed memory (an AV in `std::hash<wstring>`).

### XAML and Islands

- **A text box inside a `ContentDialog` gets no keypresses under XAML Islands** (the dialog's popup root sits outside the island's input path): use buttons-only ContentDialogs for confirms, and build anything that needs typing into the main tree (in-place editors, the cog's in-content overlay).
- **Build every ContentDialog in code.** A dialog declared in XAML is shown `TransplantedRootInPopup` (its layout moves into a popup inside the page) and is invisible to UI Automation; a dialog outside the tree is shown `EntireControlInPopup`, a window-level popup named by its title. The page declares no dialog: build it like "Close tab?" (`TabManagement.cpp`) and show it through `_dialogPresenter` (`_ShowDialogHelper` takes the dialog; strings by `RS_(L"<Uid>/<Property>")`). ⚠ A resource key read in code must exist: a Debug build fail-fasts at launch on a missing `RS_` key (`EnsureAllResourcesArePresent`).
- **Accessibility metadata goes through `AgentAutomation.h`** (`AgentSetAutomationId` / `AgentSetAccessibleName` / `AgentSetItemStatus`, change-gated values; the facet builder `AgentItemStatus`, one spelling per facet in `kAgentStatus*`). Ids follow `am.<surface>.<element>[.<key>]` (the key = the session id's first 8 characters; the list is E2E_TESTING.md §6.3; the e2e driver depends on them — add ids, never rename one). ⚠ Name only a control that has no name of its own: a control whose content is a word is named by that word, often a VALUE ("LOCAL", "MOST ACTIVE", "Auto"). Every `AgentSetTip` text is also the control's help text (`SyncHelpTextFromTip`). A rebuilt card sets its item status at build time; an in-place-edited one in every path that changes it (`SidePanelApplyCardItemStatus`).
- **A panel opened from a menu loses the keyboard to the menu's late `Closed`:** `MenuFlyoutItem::Invoke` raises Click, then closes the menu; its popup returns focus at once, but the `Closed` event comes after the close animation. A `Closed` handler that moves focus (the tab menu's GH#5750 hand-back) must stand aside while the keyboard is inside an open popup (`AgentFocusInOpenPopup`, `AgentPanelFocus.h`). **Closing a plain `Popup` that holds focus drops the keyboard anywhere** (the focus manager picks the next focusable element): call `AgentCaptureFocusReturn` before focusing the panel's box, `AgentPanelHoldsKeyboard` BEFORE the close, then `TerminalPage::_ReturnKeyboardAfterPanel`. Close such a panel on the KEY-UP of Esc / Enter when the keyboard goes to a terminal (the key's ESC / CR would reach claude: an interrupt / a submit).
- **A light-dismiss flyout eats the press that dismisses it** (`CPopupRoot::OnPointerPressed` closes the topmost light-dismiss popup and marks the press handled), whatever its `ShowMode`, and a pass-through element cannot reach into another popup. A hover-opened flyout over a button completes the click itself (`AgentLaunchBar`): arm in the flyout's `Closing` while the primary button is physically down (`GetAsyncKeyState`, or the pointer message by `GetPointerInfo`), then complete on the button's `PointerReleased` (handledEventsToo) when the press lies on the button, or by the release watch (a 15 ms timer until the release); never reopen the hover flyout while a press is armed; log every arm and completion (`[launchbar]`). Any new hover flyout over a clickable element has the same trap.
- **Popup placement:** read a focus arrival in `GettingFocus`, never `GotFocus` (XAML coerces a programmatic focus to Pointer / Keyboard before `GotFocus`); `TextChanged` is asynchronous, so mark a programmatic text write (`_programmaticTextPending`) and open nothing for its event; a popup child moves to new offsets only in the next layout pass, so anchor after it (a one-shot `LayoutUpdated`, `_ArmPathPickerReanchor`) or call `UIElement::UpdateLayout()` first — never from inside a layout-driven handler. Open the picker only on `FocusState::Pointer` / `Keyboard`.
- **A parented `Popup` can draw past its parent's clip** (its child draws in the island's popup root: the tab's tag ribbons), but opening it on an element not yet in the tree throws (`E_UNEXPECTED`, no `XamlRoot`: gate on `IsLoaded()` + `XamlRoot()` and re-arm on `Loaded`), and mutating it synchronously inside a layout-driven handler (`SizeChanged`, `LayoutUpdated`, `ViewChanged`) is a layout cycle (`E_LAYOUTCYCLE`, `0x88000FA8`): schedule one coalesced tick and mutate after layout settles. Both fail-fast as `0xC000027B`.
- **A per-element `ToolTip` on rebuilt elements leaks until the process dies:** under XAML Islands the registration `ToolTipService.SetToolTip` creates is never torn down, so each rebuilt tipped element stays pegged with its tree, accumulating into tens of GB of commit and a frozen composition pipeline. `AgentTipHelpers.h` keeps all tip state in one host per UI thread (one `ToolTip`, one open timer, a while-open watchdog; per element only attached properties and three capture-less handlers) and attaches `SetToolTip` only during a real hover-open. Never create per-element `ToolTip`s, capturing handlers or build-time `SetToolTip` on a rebuilt surface. The fixed-panel tooltips (`AgentLocalTooltip.h`: the cog, the Sessions page, the Manager page) follow the same rule: one bubbling `PointerMoved` per scope root (`AttachScope`), never per element; the root is marked (`LocalTipScopeProperty`) so the floating host yields inside it; a panel floating over content is click-through (`SetClickThrough(true)`); a window too narrow for the panel gets the floating tips.
- **A handler that captures its own element is never freed:** C++/WinRT does not collect cycles, and an element owns its delegates; a delegate that captures that element by value owns the element (and everything it holds). Reach the element through `sender` (`sender.try_as<T>()`) or a weak reference (`winrt::make_weak`), the page through `get_weak()`. A surface rebuilt on every registry change must keep its containers (the board's `BoardColumnView` columns, the side panel's cards) and refill only what changed.
- **Per-tab XAML is multiplied by ~700:** a measured `TextBlock` keeps ~17 KB of DirectWrite state (its layout, analyzer and scratch block), even on a hidden page; `ToolTipService::SetToolTip(element, box_value(text))` creates a whole `ToolTip` at once. Build a per-tab or per-row menu empty and fill it in its `Opening`, tooltips through `AgentSetTip`; measure with `tools/leakhunt` before and after (compare live objects across two dumps; check the walker against objects whose count you know).
- **A rounded element WITH children is a composition node every frame walks** (`CFrameworkElement::UpdateRequiresCompNodeForRoundedCorners`): put a childless rounded `Border` behind the content in the same Grid cell instead. ⚠ A `Grid` / `StackPanel` / `RelativePanel` / `ContentPresenter` has a `CornerRadius` too; a stock rounded template (a `Button`, a `TabViewItem`) is a node per instance — none per row in a long list.
- **A running XAML storyboard makes every display frame walk the whole composition tree** (`CXcpBrowserHost::OnTick` → `SubmitPrimitiveCompositionCommands`), however small the animation; a timer that flips a property costs a frame per flip, and a layout pass when it is `Visibility`. Looping or long animations go through `AgentAmbientAnimation` on the Composition API: `AgentOpacityLoop` / `AgentDotsPulse` for a XAML element's `Opacity` (`UIElement::StartAnimation`), composition visuals of your own for anything that moves (`SetElementChildVisual`, `AgentEmberSparks`), and `AgentLockstepBlink` for elements that must blink together (one shared clock). ⚠ Never animate a XAML element's position; a loop begins and ends on its still value; never set its `Opacity` from code while it loops; end an expression with a static set, never `StopAnimation`; get the compositor through `AgentCompositorOf` (each `GetElementVisual` forces a composition node for life).
- **An editable ComboBox handles Enter and Escape itself** (`MainKeyDown` marks them handled) and autocompletes its text on focus to the first item that starts with it: act on the key-up (arm in `PreviewKeyDown`, act in `PreviewKeyUp`), and list a pre-filled value ahead of longer ones (`PlaceSeedAheadOfLongerIds`).
- **The Manager lens is a full rebuild,** so it must know whether it is on screen and keep each card cheap: rebuild only while the page shows (`SetLensVisible`, a dirty flag otherwise), from live sessions (`SnapshotLive`, or a narrower lean read: `LiveTabBindings`, `GetTabToken`, `GetWithoutQueue`, `SnapshotLiveForScan`, `SnapshotLiveForCards`, `HeadlinesOf`), with menus built in `Opening` (`_MakeLazySessionMenu`), file reads cached by stamp, and no disk, registry or syscall work per card; route every trigger through `_Refresh` (AGENT_MANAGER.md *Rebuild cost*). A terminal's ticket lock (`til::recursive_ticket_lock`) held by its output or render thread blocks the UI thread's pointer handlers; a slow tab switch logs `[tab-switch-slow]` / `[tab-switch-settle]`, and `tools/livesample.exe lockwatch` names the holding thread (⚠ it suspends threads: dev only). Which thread holds such a lock for seconds is not attributed yet.

### The tab strip

- **MUX TabView drag-start null-deref (WinUI 2.8):** dragging any tab on a scrolled, overflowed strip crashes inside `Microsoft.UI.Xaml.dll`, before any event reaches us. WUX reports the tab's Content (Windows Terminal's unique `Border`) as the dragged item, MUX's `FindTabViewItemFromDragItem` misses both fast paths and loops `ContainerFromIndex(i).Content()` from index 0, and a derealized container is null (`0xC0000005`; a swallowed variant leaves the app wedged instead). So native drag is permanently off (`CanReorderTabs(false)`, `CanDragTabs(false)`, every `TabViewItem` `CanDrag(false)` through `_ApplyTabDragPolicy`), and reorder, tear-out and cross-window docking are Agentmaster's pointer-owned gesture ([`TAB_STRIP.md`](doc/agentmaster/TAB_STRIP.md) *Dragging tabs*). ⚠ No workaround inside MUX holds: a `ListView`'s `ItemsPanel` must be an `ItemsStackPanel` / `ItemsWrapGrid` (a plain `StackPanel` crashes the render pass), and a Content that already has a parent crashes `UpdateTabContent`. Route every `TabItems()` mutation through `_SettleTabStripLayout()` and `_ApplyTabDragPolicy`.
- **The tab strip virtualizes:** `StartBringIntoView` silently does nothing on a tab that is not laid out, and the strip ignores bring-into-view requests on purpose (`BringIntoViewOnFocusChange(false)`): reveal a tab only through `_RevealTabInStrip` (pure math `DecideTabStripRevealOffset`). Never derive a scroll offset from a tab index (the extent is an estimate); never `ScrollIntoView` a tab not laid out yet; select a new tab before settling the strip, and never settle right after a new tab's content swap; add per-selection effects to `_ApplyAgentTabSelection`, never inline in `_OnTabSelectionChanged` (TAB_STRIP.md *Revealing a tab*).
- **A `TabViewItem` never clamps its children's desired size** (a ListView item on an ItemsStackPanel is a non-clipping subtree): the tab lays its content out wider than itself and clips it. Bound every header child that can grow: a Grid star column + `TextTrimming`, or `MaxWidth` (`TabHeaderControl.xaml` `HeaderTitleRow`).
- **A `TabViewItem` takes every mouse or pen LEFT press before your handler** (`ListViewBaseItem::OnPointerPressed` marks it handled; the selection happens on the release): register with handledEventsToo, tell an inner control's press apart by walking `OriginalSource` up to the item (`ResolveTabPressTarget`), and keep a click from selecting by marking its release handled below the item (`_ArmTabShiftActivateRelease`). Every ListView / GridView item behaves the same.
- **`_updateAllTabCloseButtons()` re-applies the theme's close-button visibility to every tab** on every theme or settings apply: a tab that must keep `CloseButtonVisibility::Never` needs a skip in that loop (and drag and the menu's Close / Move are separate axes).

### Windows, packaging and identity

- **Never reuse the `WindowsTerminalDev` package identity** (the `K:\source\windowsterminal` checkout owns it; registering it here fails with `0x80073CF6 / 0x80070020`), **and keep every runtime identifier package-aware:** upstream's `GetWtExePath` resolves `<PFN>\wt.exe` (absent in our packages) and `windowClassName` (the single-instance mutex and window class) was built from the branding alone. Agentmaster picks the alias by PFN prefix (`AgentmasterDev` first) and appends `GetCurrentPackageFamilyName()`. Launch an alias by name (`agentmaster.exe` / `agentmasterdev.exe`); a full reparse-path launch bypasses it (ShellExecuteEx on the full `<PFN>\<alias>` path is the verified exception).
- **Closing instances to relink:** ask the user first; stop the GUI process only (`Agentmaster.exe`), path-filtered to the slot being redeployed — a broad filter also matches the release layout, which may host your own session. ⚠ Never stop `OpenConsole.exe`: a host killed outright skips its graceful shutdown (`CTRL_CLOSE_EVENT` to every client), and its tab's pwsh + claude.exe (+ MCP children) live on with a dead console, feeding a newer instance phantom hooks through `bridge.json`. Stopping the GUI closes its pipes, and each host ends its clients and exits: wait for them to drain. Never touch the Store Windows Terminal; never blanket-`taskkill` by image name.
- **Packaging fails `PRI210 / 0x800704c8`** when the registered layout's `resources.pri` is memory-mapped (by the package registration, no user process): the binaries are already linked; delete that `resources.pri` and build again so MakePri creates it.
- **MSIX virtualizes a packaged app's `%LOCALAPPDATA%`** to the package's LocalCache, but the spawned `claude.exe` is external and reads the real filesystem: every file the two share (the hooks config, the `--settings` path) lives in the profile under `%USERPROFILE%`. A Browse…-picked profile is a real filesystem folder (`FOS_FORCEFILESYSTEM`).
- **A PATH longer than 8191 characters makes cmd.exe resolve NO command** (System32 included; `cmd /c` exits 1 "'x' is not recognized"), so Claude's Ctrl+G external editor dies "Edit quit unexpectedly (exit code 1)" and every `cmd /c` breaks. `CmdPathLimit.h` compacts the process PATH first thing in `WindowEmperor::HandleCommandlineArgs` and every tab's final env block in `ConptyConnection::_LaunchAttachedClient` (only duplicates and empties, then provably missing folders; `[path-guard]`); it never writes the registry — the machine fix is cleaning the User Path. Reproduce a console-app failure with the tab's real environment before blaming Agentmaster code. Builds from bash need a short PATH too (vcvars and `GenerateFeatureFlags.proj` run through cmd.exe).
- **A GPU driver's DLL init can deadlock the startup:** `App{}` starts XAML's GPU thread, NVIDIA's `NvMemMapStoragex.dll` calls `SHGetKnownFolderPath` from its DLL init while the loader is busy, and the main thread's first known-folder lookup holds `windows.storage`'s cache lock while it needs the loader (ABBA). `StartupGuard.h` resolves every startup folder and flag combination on the main thread before `App{}` (`kStartupKnownFolderLookups`: ⚠ add any new startup-time `SHGetKnownFolderPath` combination) and a 25 s watchdog terminates a hung launch once per episode (`[startup-hang]`). A stuck process cannot relaunch itself (`CreateProcessW` blocks, a new thread never runs). Crash dumps are keyed by exe name: `HKLM\…\Windows Error Reporting\LocalDumps\Agentmaster.exe`.
- **Every shown terminal owns its own D3D11 device:** past ~62 in one process the NVIDIA driver hang-recovers at every new tab or focus (System log `nvlddmkm` event 153), and a tab opened then can stay BLACK while its claude runs (WARP never loads; nothing retries). Read its console first (the am-agentmaster-cli skill's `am_inspect.py screen`): a ready input box behind a black tab is rendering. Remedies: Software rendering, closing viewed tabs, a restart. Hidden terminals draw nothing and release their device after 60 s (RENDERING.md §4c). ⚠ A suspended render thread parks on `_suspended` (`_waitWhileSuspended`): whatever must wake it (teardown, a resume) changes that flag first.
- **DWM iconic thumbnails:** with `DWMWA_FORCE_ICONIC_REPRESENTATION` + `DWMWA_HAS_ICONIC_BITMAP`, Alt+Tab shows the pre-selected window BLACK when DWM holds no bitmap (and never asks again that time), and DWM keeps the first peek bitmap forever without an invalidation: always `DwmInvalidateIconicBitmaps` and then `DwmSetIconicThumbnail` at once. A bitmap larger than DWM's box (from `WM_DWMSENDICONICTHUMBNAIL`'s lParam: HIWORD width, LOWORD height) gets `E_INVALIDARG`; `PrintWindow` without `PW_RENDERFULLCONTENT` captures a XAML Islands window black.
- **Symbolize a crash without a debugger** with the in-box DIA SDK (`msdia140.dll`, `findSymbolByRVA`, `findLinesByRVA`) and DbgHelp (`MiniDumpReadDumpStream` for the exception, thread and module streams): the debug-dumps skill. The WER Application Error event gives the faulting module, the code and the RVA; full dumps land in `%LOCALAPPDATA%\CrashDumps\`.

### Claude Code and hooks

- **`--dangerously-skip-permissions` does NOT skip the workspace-trust dialog.** A workspace is trusted only when `CLAUDE_CODE_SANDBOXED` is truthy, an in-memory session flag is set (`-p`, background-agent mode, accepting the dialog), or `~/.claude.json` `projects.<key>.hasTrustDialogAccepted` is true for the cwd's key or an ancestor's (the key: the cwd's git toplevel, `path.normalize`d, `\` → `/`, no trailing separator, case-sensitive). No settings or policy knob exists; accepting at the home folder is never persisted, so `%USERPROFILE%` asks on every launch. The flag also leaves the one-time global "Bypass Permissions mode" acceptance. Agentmaster pre-trusts at the launch seams (`EnsureClaudeWorkspaceTrusted`, HOOKS.md *Workspace trust*).
- **An unanswerable startup modal is invisible in our UI:** a tab parked on a startup dialog fires no `UserPromptSubmit`, mints no transcript id, and shows only `○ claude · unlinked` (no card, no dot, no runner; a /handover paste would be typed into the menu). Check a new spawn flag or claude version with a PTY probe in a throwaway folder (HOOKS.md *Workspace trust → Verifying it*). An isolated `CLAUDE_CONFIG_DIR` raises an "external CLAUDE.md imports" dialog that real configs never show.
- **`claude --resume <id>` dies with "No conversation found"** when the session never got a prompt: gate resume on the transcript on disk (`ClaudeConversationExists(id)`, a glob over `<CLAUDE_CONFIG_DIR | ~/.claude>/projects/*/<id>.jsonl`), never on the persisted state (Rule #6).
- **Native-exe-only:** ConPTY's `CreateProcessW` appends only `.exe` and ignores `PATHEXT`, so a bare `claude` misses the npm `claude.cmd` (`0x80070002`). Launches run the native `claude.exe` by full path (`ResolveClaudeExe`, before the PATH shim is prepended: the Settings override → PATH `claude.exe` → `~/.local/bin` → a `claude.cmd`'s npm native binary → `Engine::claudeExePath`); with none, `ClaudeAvailable()` is false and every claude action is gated behind "Claude not detected" (Browse…, `claude install`), with `_LaunchClaudeSession` refusing (`[launch-blocked]`). A pure-Node claude is unsupported.
- **A ConPTY connection starts on the control's first non-zero layout,** in the layout pass that first sizes its SwapChainPanel (`_SwapChainSizeChanged` → `_StartTerminalInLayoutPass`, with a `LayoutUpdated` belt held only while the control is loaded and unstarted). Never `Start()` it early from the app layer (output before `ControlCore::Initialize` AVs in `Microsoft.Terminal.Control.dll`), and never move the start to `Loaded` alone: XAML lays a tree out before hit tests, outside its frame tick. Every pointer, wheel and scroll-bar input waits for `_initializedTerminal` (the input gate); keep any new input path behind it.
- **The hook wire's `prompt` field must be escaped**, identically in `WireEscape` and the PowerShell forwarder: `\` → `\\` first, then tab / CR / LF → `\t` / `\r` / `\n` (PowerShell: `-replace '\\','\\'` before the others). The PowerShell side is the one seam the C++ tests can't cover: check it with a parity run.
- **The hook forwarder decodes its stdin as UTF-8** (a UTF-8 `StreamReader` over the raw stdin; `[Console]::In` decodes in the console's code page and garbles every non-ASCII prompt) and reads files with `Get-Content -Encoding UTF8`. ⚠ Never set `[Console]::InputEncoding` (it re-code-pages the console shared with claude). The forwarder file carries a UTF-8 BOM (PowerShell 5.1 parses a BOM-less `.ps1` in the ANSI code page) and its body stays ASCII.
- **A shell-form hook pays Git Bash + the user's `BASH_ENV` on every run** (0.2–15 s), and **SessionEnd's whole phase gets 1.5 s** unless a hook declares a `timeout` (the largest wins, capped at 60 s, and becomes the ceiling for the user's own SessionEnd hooks). Agentmaster's hooks are exec form for claude ≥ 2.1.139 with timeouts (10 s, SessionEnd 5 s). ⚠ Never hand an exec-form file to an older claude: it runs the bare `command` through its shell without the `args`. Each transcript records every hook run as `attachment` lines (`hook_success` / `hook_cancelled` / `hook_error`, `durationMs`, `timedOut`, `stderr`).
- **A `+` tab's claude does NOT inherit Agentmaster's runtime env** (`AM_SESSION`, `CCMGR_HOOK_PIPE`, the PATH shim): Windows Terminal regenerates a new tab's env from the registry, so a hand-typed claude there fires no hooks. Bind by the roster correlation (Rule #13).
- **A managed session's conversation id can diverge from its launch id:** `/resume` and `/clear` switch a live claude's `session_id`, while the launch id stays on its command line (`--session-id`) and in `CCMGR_SESSION_ID`. The forwarder takes the payload's `session_id` first (the env is the fallback), and the observer prefers claude's own pid-validated presence row over the command line. ⚠ Open: the scanner skips a session with no transcript (nothing to tail), so a live record left without one is never released by the pull side; and a `/resume` of a conversation another tab runs makes two claudes write one transcript (only the host tab binds: OBSERVER.md §20).
- **A `--fork-session` fork fires its first `SessionStart` under its SOURCE id** (claude is resuming the source at that instant). The fork records `SessionInfo::forkParentId` and its ConPTY's `tabToken` is stamped at launch, so the registry ignores that echo for a live fork (`[fork-echo] ignored …`; one-shot: cleared on the fork's first own-id hook).
- **A `--fork-session` fork writes no transcript until its first turn.** On reopen a never-messaged fork re-forks from its source into the same id (`forkParentId` is persisted; `BuildClaudeSpawn`'s `forkIntoSessionId`; `[restore->refork]`), and every display surface reads the source's transcript until the fork has its own (`ResolveClaudeDisplayTranscript`, prepending `ForkSourceTranscriptNote` where it copies; ⚠ never cache the fallback path; the mechanics keep `ResolveClaudeTranscriptPath`). A never-prompted Codex fork has the same gap and no fix.
- **Claude's Ctrl+S stash is not a discard:** it auto-restores into the box ~0.4 s after the next submit, so a clear that stashes and walks away re-plants the draft. Only the draft swap may stash, because its restore always consumes the slot. `Esc` interrupts a running turn even with text in the box (a fast double-Esc on an empty box opens the Rewind menu); `End`+`Ctrl+U` and `End`+backspaces are true discards and safe mid-turn (the mail move's `DecideDraftDiscard`).
- **Claude Code (2.1.277 and later) cancels an Enter that finds an "invisible" character** (zero-width, bidi controls and marks, tags, variation selectors, C0/C1, SHY, fillers; VT / FF / NEL / LS / PS / a lone CR become LF), leaving the cleaned text in the box. The rule is context-sensitive (an emoji's VS16, emoji and Indic joiners, Thai ZWSP, a Persian ZWNJ, an LRM / RLM on a Hebrew or Arabic line are kept), so never approximate it: type text into a Claude box only through `BuildPromptFill` (sanitized by `ClaudeInvisibleChars`, pinned to claude's own outputs by a generated oracle table; re-run `tools/claude-invisible-oracle/` when Claude Code changes the rule) and compare prompts only through `NormalizePromptTextForCompare` (NFC; the editor holds NFC text). The editor deletes by grapheme cluster (`CountGraphemeClusters`).
- **Claude Code's fullscreen renderer lives in the ALTERNATE screen buffer** (`CLAUDE_CODE_NO_FLICKER=1`, `/tui fullscreen`, or a server-side flag): its whole UI, the input box included, is drawn there, with mouse tracking on and no terminal scrollback. Never skip the alt buffer when reading Claude's box; tell a child app (an editor, a pager) apart by content (the caret between anchored rules). Under fullscreen the summary jump reaches only prompts on claude's current screen. A blind box reader shows as `[advance-skip] … (input box not visible)` across the whole fleet with no `[pending]` lines; `tests/pending_probe.exe <claude-pid>` (in `AgentMaster/`) shows what the detector sees.
- **A message typed while claude works is a `queued_command` attachment**, not a `user` line: `{"type":"attachment","attachment":{"type":"queued_command","commandMode":"prompt","prompt":…,"origin":{"kind":"human"}}}` (no `origin` in older builds), written when the running turn absorbs it; one the turn does not absorb is submitted as a normal `user` line. The same type carries machine traffic (`commandMode:"task-notification"`, `origin.kind` `peer` / `task-notification`). The summary reads human ones (`SeExtractQueuedHumanPrompt`); the Sessions page's 👤 search and msgs count, the External plan and the MOST RECENT sort miss them. Any new reader that lists the user's messages must handle both shapes.
- **A windowed tail reader must not gate its read on the file size alone:** a finished turn never grows its file again, so a reader that consumes ≤ 1 MiB per pass needs a "caught up" bit beside its change gate (`ShouldReadTranscriptDelta`), and anything that judges the tail waits for it (`ScanState::readReachedEnd`). When a session reads the wrong state, replay the reader's exact chunking over the real transcript first.
- **A killed agent leaves its fullscreen terminal modes on** (the alternate screen, mouse tracking, focus reports, kitty keyboard flags, raw VT input), and PSReadLine then types every mouse move as text. The managed host wraps the agent in a console guard (`WrapPwshScriptInConsoleGuard`, `ClaudeSpawn.h`): it saves the console modes through PowerShell's own `ConsoleControl` methods, and after the agent writes a VT reset, restores the modes and, on a non-zero exit, prints a note naming Restart session. ⚠ Call those methods directly (a value passed through `$args` arrives wrapped and `MethodBase.Invoke` refuses it); write the reset BEFORE restoring the output mode; the guard costs ~2,250 command-line characters (`kHandoverPromptEscapedBudget` is 10,000). A killed claude never reaches Done (only its `SessionEnd` sets it): open. Probe kit: `tools/console-guard-probe/` (run its probes with `< /dev/null`).
- **The claude-agent-sdk-cpp submodule:** compile Agentmaster's `ClaudeSdkProcessWin32.cpp`, never the SDK's `process_win32.cpp` (its `has_data(timeout)` ignores the timeout and spins a core; it is ANSI-only and cannot remove an inherited variable) — after a move of the pin follow SDK_HARNESS.md §9. `--autocompact N` alone never compacts under `--setting-sources ""` (claude falls back to `~/.claude.json`): the `--settings` text carries `"autoCompactEnabled": true`. `nlohmann::json member{ other }` builds a one-element array (use parentheses). A tool handler runs on the SDK's reader thread: return fast, and let a slow one check its request generation. Claude Code lowers a permission mode it does not allow silently (read it back; `--restricted` refuses with an error). With bypass the tool list is the only limit. Never run `harness_live.exe` against a real profile (a release-hosted shell carries the live `AGENTMASTER_PROFILE`).

### Engine, threads and data

- **A `fire_and_forget` coroutine can drop the LAST page reference on a pool thread,** so the whole UI tree destructs off the UI thread, where a UI-affine call in a destructor (`DispatcherTimer.Stop()`) throws inside `noexcept` and terminates the whole process (`0xC0000409`). Every destructor reachable from a page teardown wraps UI-affine calls in `try { … } CATCH_LOG();` (with release lines outside the try, and thread-safe engine detaches bare); every `fire_and_forget` catches everything (an escape is `winrt::terminate`; split a body that needs `co_await` into an awaited `IAsyncAction`); a catch that re-arms a latch keeps doing so.
- **The exception-forensics logging path never logs its own failures:** the chain `LogSwallowedException` → `LogSwallowedExceptionCore` → `ExcLogThrottleAllow` / `CaptureRecentThrowStacksText` → `FormatAddressModuleRva` → `AppendStateLog` → `AgentmasterStateDir` would recurse, and `AppendStateLog` holds a non-recursive mutex, so it would deadlock first. The nine `catch (...)` blocks on it in `ClaudeSpawn.cpp` stay bare, each marked `⚠ DELIBERATELY BARE` under the `LOGGING-PATH RECURSION RULE` block (the classifier's `"unknown exception"` catch is not one of them).
- **Working-directory comparison is filesystem-aware:** Windows is case-insensitive and treats `/` as `\`; POSIX is case-sensitive. Route every folder grouping, scope and match through `PathEq` / `NormPath` / `NormDirKey` (`CompareStringOrdinal` with ignore-case on Windows), never a raw `==` or `find` (Rule #8).
- **DuckDB's memory limit binds per TRANSACTION, not per statement** (the service runs at 1 GB; never leave `memory_limit` unset): merge the hot tier in slices (`TextIndex::Merge`, ~64 MB per transaction), sort large copies in slices (`PlanLineSlices`), commit a re-cluster's tables one by one with only the swap in one transaction, and back off a failed maintenance step (`kReclusterBackoff*`). `pragma_storage_info(t)` takes a literal only; `pragma_database_size()`'s `used_blocks` is the reliable size. Never point a one-shot mode (`sql`, `recluster`, `resync`, `verify-summary`) at a profile whose service runs: DuckDB allows one writing process per file.

## Correctness rules (do not regress)

1. **A session is ready for an automatic send only when it is at rest and settled.** Ready = turn-complete (`Stop` → `WaitingForInput`) or `Idle` with no turn in progress (a freshly launched or resumed plan must start without the `Stop` it will never emit); `Running`, `NeedsApproval`, `Error` and `Done` are never ready.
   - **One prompt per turn:** the pickup guard holds a change-driven advance until the sent prompt is picked up, so the queue never drains into one turn.
   - **Settled:** an automatic send waits until the session has held a sendable status for `kStateSettleMs` (40 s) since the later of its last status change and the prompt's queue time; every further change restarts the wait (the STATE SETTLE hold, DELIVERY.md §16). Never type into a momentary "ready".
   - **Questions:** `Notification(permission)` → `NeedsApproval`, which the queue never answers (nothing auto-approves; `ApprovalPolicy` is a persisted placeholder no code evaluates). A `Stop` whose last message is a question keeps the next prompt `Pending` (the question-guard) until a turn-complete that asks nothing, or an explicit re-arm. The guard never parks a prompt in `Held`, a legacy status the scheduler turns back into `Pending`.
2. **Tree `Enter` = Activate** (jump to the session's live tab); never forward it to `ITerminalConnection::WriteInput` (that would submit a stray carriage return).
3. **Bind a queue and an injector to a session id**, never to "the selected session" at send time.
4. **Idempotent sends:** mark a prompt `Sent` atomically and persist it before the injection; a restart never replays a `Sent` prompt (it loads with `echoed=true`), and a failed injection rolls the prompt back to `Pending` on every path.
5. **Backstops:** stop-on-error, `maxAutoSends`, the global pause (one process-wide state, `Scheduler::SetGlobalPause`), the automatic pauses (the Enter-retry give-up, the lost-send verdict, the merge verdict) and the interrupt hold. Pause-on-human-input is configured and checked but has no feeder (`SessionRegistry::NoteHumanInput` has no caller): don't count on it.
6. **Startup loads every session closed; a reopened window's tabs come back dormant; a restore resumes, never replays, and is transcript-gated.**
   - At startup every persisted session loads as closed (`live=false`). Only the tabs of a reopened window come back (`_RestoreWindowTabs`), each DORMANT: its claude starts when the tab is first shown, or through the restore wake when its turn was in flight (PERSISTENCE.md §14). Every other session is resumable from the Sessions browser.
   - A resume runs `claude --resume <id>` (the same id, so hooks still correlate) only when Claude has a transcript for that id (`ClaudeConversationExists`), else a fresh session (a new id, the same folder and queue; the stale record dropped), or a re-fork for a never-messaged fork. Queues reload with their statuses.
   - **Close is the only close verb, and it always archives:** the `live=false` record stays and the session stays resumable; there is no Delete (FAVORITES.md). Mark a session to keep with the ★ favorite.
   - **Agentmaster never deletes or rewrites a Claude transcript.** Its one write is an appended rewind line, before a resume continues a turn that ended in an API error or one the user chose to continue after an interrupt (HOOKS.md *API-error turns*, *Interrupted turns*), and never while a claude runs that conversation.
   - Never decide resume-vs-fresh from the persisted `SessionState`. The persisted state seeds only the DISPLAY: the at-rest "needs you" states (`WaitingForInput`, `NeedsApproval`) survive a crash and the others load as `Idle` (`RestoredSessionState`, Rule #16). Every seam that applies it to a Claude record first records a turn in flight (`RestoredMidTurnFlag` → `SessionInfo::midTurnAtRestore`), so the scanner reads a turn that never finished, and that no process can be running, as `Error`, never as a ready `Idle` (HOOKS.md *Cut-off turns*). ⚠ A new seam that normalizes a record must set the flag too.
7. **State comes from hooks, the transcript and claude's own heartbeat — never from the screen** (the Ink TUI repaints constantly). The screen is read only for facts no hook carries (the unsent draft, an open menu: PENDING_INPUT.md), and a fact never sets `SessionState`.
8. **Same directory = same path, filesystem-aware.** Group, scope and match sessions by working dir through `PathEq` / `NormPath` / `NormDirKey` (case-insensitive on Windows, case-sensitive on POSIX), so case variants of one directory never fork the Explorer Tree into two roots.
9. **Adopt only on `SessionStart`; bind by `tabToken`, never guess.** A hook for a session we did not launch creates an `external` record only on `SessionStart` (any other event for an unknown id is ignored: there is no connection to bind); the Fleet Observer's first sight of a claude creates one too (Rule #13). Promotion to control correlates the `WT_SESSION` `tabToken` to a live ConPTY and binds the injector to THAT id (Rule #3); with no matching connection (a claude hosted outside this app) the session stays observe-only. Never bind to "the active tab".
10. **One engine per process; a closing window detaches; records reference, never copy.**
    - Exactly one `SessionRegistry` / `HooksBridge` / `Scheduler` / `SessionScanner` / `ProcessObserver` for the whole process (`SharedEngine()`), shared by every window. Never create them per `TerminalPage`, and never key the bridge on anything that collides across windows (the `<pid>` pipe is unambiguous because there is one bridge).
    - Each window registers its lens observer, adoption handler and every per-window sink (activate, close, deactivate, restart, session actions, dock target, agent tools, command actions, …) by token and detaches them on teardown (`RemoveObserver` in `~AgentManagerContent`; the rest in `~TerminalPage`).
    - The fleet loads once per process under the `Engine::restoreMutex` barrier: a second window blocks until it is loaded, then skips, so it neither inserts twice nor re-homes tabs against a half-loaded registry.
    - A window's persisted UI state (geometry, lens, ordered tab refs) is its `WindowRecord` (`windows/<id>.json`), which references sessions by id and never copies them: `sessions.json` + `SessionInfo.live` are the one session source of truth (Option 1).
11. **A session's title is ONE value: Explorer name == tab title == persisted `SessionInfo.title`.** Don't add a separate tab title, and never take the name from claude's OSC title.
    - **Two channels on a tab:** the user-rename override `Tab::_runtimeTabText` and the active control's OSC / profile title. `Tab::Title()` returns the override when set, else the control's title; **`Tab::GetTabText()` returns only the override.** A managed tab pins the override (`Tab::SetTabText`) at launch, restore and adopt, so claude's OSC title is hidden and can never reach the registry (the OSC handler only calls `UpdateTitle()`). An unbound `+`-tab claude floats with its OSC title until the observer binds it.
    - **Both directions write the one value and persist:** an Explorer **Rename…** → `_RenameClaudeSession` (registry + tab); a tab rename (double-click, **Rename Tab**, `renameTab` — all through `Tab::SetTabText` → `PropertyChanged("Title")` → `_UpdateTitle`) → `_SyncClaudeTitleFromTab`, which reads the override, never `_GetActiveTitle()`. A rename in a window that does not host the tab writes the registry, and the hosting window re-pins (`_SyncClaudeTabTitleFromRegistry`, reading the title fresh on the UI thread, never a captured snapshot). Equality guards make an in-step sync a no-op; an emptied override (`ResetTabText`) re-pins.
    - **Every registry → tab pin goes through `_SetClaudeTabTextPinned`** (the `_pinningClaudeTabTitle` latch, UI thread, one stack frame): `SetTabText` synchronously re-enters `_SyncClaudeTitleFromTab`, so a raw pin mirrors our own write back into the registry, and a stale async write-back then ping-pongs the two directions forever.
    - **Normalized on both entry points** (`_CommitRename`, `_SyncClaudeTitleFromTab`): surrounding whitespace and newlines are trimmed (the tab re-pinned to the trimmed value), and a blank rename is rejected (the managed name re-pinned). `DeriveSessionTitle`, the default from the working dir, is never empty and seeds only an untitled session.
    - **Adopt:** a name the user already gave the `+` tab wins (mirrored into the registry). **An in-session `/resume`** (`_BindClaudeSessionToTab`'s `reHomedFromOtherId`) keeps the new conversation's own title (its registry title, else `DeriveSessionTitle`) and never inherits the superseded conversation's pinned text. **A fork's name** comes from `DeriveForkTitle`: ` (fork)`, then ` (fork 2)`, ` (fork 3)`, … — never ` (fork) (fork)`.
    - **Persistence by tab kind:** a managed tab persists as a session-id ref in its `WindowRecord` (the title lives in `sessions.json`); a shell tab persists its override as a `RenameTab` action in `actionsJson` (`BuildStartupActions`). The two never overlap.
    - **Display titles from transcripts are separate:** the Sessions browser, the CLI and the External rows derive one with `PickDisplayTitle` (`customTitle` > `aiTitle` > summary > first prompt), display-only; it is never written over a managed title (a resume or fork from disk seeds a title only for a session unknown to the registry).
12. **A tab's color is ONE value per COLOR KEY, and it is PERMANENT.**
    - **The key follows `tabColorMode`** (Settings ▸ Tabs ▸ Tab coloring): the working dir (default), the session itself (`Individual`: the color lives on `SessionInfo::tabColorHex`, never in the dir map, and nothing fans out), or the inferred working dir (`InferredWorkingDirectory`: the dir machinery keyed by `SessionInfo::inferredWorkingDir` when known, else the cwd). `SessionColorKeyDir` is the one key resolver, `ResolveSessionColorHex` the one read every display surface shares, and every paint routes through `_ApplySessionTabColor`.
    - **A git worktree keys its main repo's color** in the dir-keyed modes (`SessionColorKeyDir` → `ResolveWorktreeMainRoot`, memoized), the one place the color key differs from `EffectiveWorkingDir`, which stays worktree-granular for grouping and mechanics.
    - **Remove colors (`NoColor`) suspends painting, strip-wide:** a managed tab is reset; every other tab's runtime color is parked on the tab (`Tab::SetTabColorSuspended`; persistence still records the parked value through `GetPersistableTabColor` / `BuildStartupActions`); "Change tab color" and `openTabColorPicker` are disabled on every tab (`Tab::SetColorPickerEnabled`); a color that lands meanwhile is parked by the `_OnClaudeTabColorChanged` chokepoint; the persisted maps are neither read nor written. Switching back restores exactly the previous colors.
    - **The dir-keyed contract:** every tab in a dir (`NormDirKey`) shares one color, kept across tabs, windows and restarts. `dir-colors.json` (schema v2) is the single source of truth, holding user picks and auto-assigned colors alike (no in-memory cycle state). A launch, restore or adopt paints the dir's persisted color (`_ApplyDirColorToTab`), else `AssignDirAutoColor` deals one and persists it.
    - **The deal** (`ChooseDirColor`, pure): an assigned dir keeps its color; else the first color in the dir's seeded probe order (Fisher-Yates / splitmix64 over `(seed, key)`) that no other dir holds; once every palette color is assigned, reuse is allowed but still avoids every color an open tab shows (all windows, the registry's live set); only when every color is on screen is a duplicate unavoidable (the dir's preferred slot). The seed (`SeedDirColors`, random, at engine init) only randomizes a dir's first assignment.
    - **A user's pick** (`Tab::SetRuntimeTabColor` / reset → `TabColorChanged` → `_OnClaudeTabColorChanged`) persists for the dir and recolors every live tab in it (Rule #8); a reset drops the entry. One de-dupe (`GetDirColor(dir) == newHex`) makes our own writes no-ops, so only a genuine new pick re-persists and fans out. A schema-v1 file is de-collided once at engine init (`MigrateDirColorsToV2IfNeeded` → `DeCollideDirColors`: colors kept where possible, duplicates reassigned, off-palette picks kept).
13. **Fleet Observer: rostered == ours; correlate by `WT_SESSION`, never guess; push wins for state.**
    - A claude correlated to a tab in OUR published roster (its shell is the ConPTY root of one of our tabs) runs in one of our windows, so it is ours (`RunningApp::Agentmaster`) and bindable **regardless of `AM_SESSION`**, which a `+`-tab claude does not inherit (Gotcha). `AM_SESSION` only classifies the claudes outside the roster (a background process we started, another instance's, a real Windows Terminal's).
    - Correlation keys on the exact `WT_SESSION` (== `ITerminalConnection::SessionId()`) — never PPID ancestry, a stale tab cwd or "the active tab". When one conversation runs in two or more tabs, only its host tab binds (`PickConversationHost`; OBSERVER.md §20).
    - `ObserveClaude` enriches facts and **never sets `SessionState`**: push hooks and the transcript tail own state (Rules #1, #7), so a hooked and an un-hooked claude converge on one record. The enrichment fields are never persisted; the observer re-derives them each run.
    - The observer only reads (PEB, Toolhelp, the filesystem) and never writes to a shell's stdin (the invisibility invariant); its one action is ending an orphaned console group (OBSERVER.md §13a). **Adopt** keeps this: it never injects into or ends the foreign process; it resumes (or forks) that conversation into a new managed tab (`claude --resume <id>`, transcript-gated) and leaves the original running.
14. **Conversation identity: claude's own heartbeat, then an explicit id, then the transcript's CREATION time — never the newest mtime.** A live claude's conversation is its pid-validated presence row (`~/.claude/sessions/<pid>.json`, `PresenceRowMatchesProcess`) when it has one; else an explicit `--session-id` / `--resume <guid>`; else `ResolveSessionId` picks the cwd's transcript whose creation time is closest to, and not significantly before, the process start, rejecting older ones. This keeps two claudes in one cwd bound to their own conversations, and resolves a never-prompted claude to `""` (no card until its first prompt) instead of a stale transcript.
15. **One profile per install, resolved once, before any state read; everything persists inside it.**
    - The WindowEmperor resolves the profile after the single-instance handoff and before the first settings or state read. An installed copy's first launch selects its per-identity default without UI (release → Default, dev → Development); a portable copy asks first where to live and which profile (PROFILES.md §2a / §2b). No picker is ever shown from a handed-off or `-Embedding` process, and library-side resolution (`ProfileBootstrap::ResolveProfileDir`) never shows UI: a headless host (tests, tools) lands on the per-identity default, `~/.agentmaster` when unpackaged.
    - Read and write persisted state (engine files, Terminal's settings, window records, the reopen scan) only through `AgentmasterStateDir()` or the `AGENTMASTER_PROFILE`-redirected `GetBaseSettingsPath()`. The resolution is cached for the process: a profile change applies at the next start, and state never moves mid-run.
    - Outside a profile live only the pointers to it (`%USERPROFILE%\.agentmaster.profiles`, the env override, the exe-side `profile.path`) and the build lock dir `%USERPROFILE%\.agentmaster\locks\` (*Runtime state dir* lists every other write outside it).
    - Generated artifacts that embed paths or live endpoints (the shim, the hooks settings, the forwarder's `bridge.json` discovery) are derived from the ACTIVE profile at engine init: a fixed `~/.agentmaster` in generated content is a cross-instance routing bug.
16. **Durability: never lose a window, tab or session unless the user closed it deliberately, and even then demote it to recoverable, never erase it** (PERSISTENCE.md §13.5, FAVORITES.md). The workspace survives every exit: a close, a quit, a crash.
    - **Three durable layers** in the active profile (Rule #15): `windows/<id>.json` (one `WindowRecord` per window: geometry, lens, ordered tab refs, the focused tab), `open-windows.json` (the windows open at exit), and `sessions.json` (the fleet; it only grows).
    - **"Closed one at a time" decides only auto-reopen vs on-demand recovery,** through the manifest's skip-empty rule (`Engine::UnregisterLiveWindow`): each unregister rewrites the manifest except a write that would empty it. Closing windows one by one prunes each; the last close leaves the final snapshot; a hard exit leaves the full set. A closed window's record stays on disk and is offered by **Reopen Windows (N)** (`RecoverableWindows` = records − live − content-less). The Emperor reopens manifest ∩ records, asking first when more than one; **No** loses nothing.
    - **Sessions:** Close always archives (`live=false`; the record, queue and runner mode kept; the transcript untouched); a closed session is resumable from the Sessions browser, and a recovered window brings its tabs back.
    - **Enforcement:** the close / quit flush captures the record BEFORE teardown clears `_claudeTabs` (`CloseWindow` / `RequestQuit`, latched by `_windowRecordTeardownFlushed`; `~TerminalPage` catches the other windows of a quit-all), and it is the window's LAST write — once latched, `_FlushWindowRecord` refuses (`[window-save] <id> late save refused`) and `_ScheduleWindowRecordSave` arms nothing, since a save still pending at the close would run after the archive and record the Claude tabs as shells. The load barrier (`Engine::restoreMutex`) keeps a second reopened window from flushing an empty record over its workspace; the anti-clobber guard refuses a pre-`Initialized` capture, and one with no tabs and no geometry; the reclaimable pool re-claims a record closed this run BY ID, so a reopen never mints a lens-less duplicate. ⚠ A new teardown seam must flush before it sets the latch, and archive only after both.
    - **The only two erasures, both content-free:** a window left with no tab self-closes and deletes its record (`_CloseWindowIfManagerOnly`, race-safe through `ReserveManagerOnlyClose`; the last window stays open, its record discarded), and a session whose transcript vanished from disk stops being listed (Claude never sweeps: `cleanupPeriodDays` is seeded to ~never).
    - Never add a destructive close path, a manifest write that can empty the file, a capture that runs after `_claudeTabs` is cleared, or a `sessions.json` prune that drops a record with a live transcript.
    - **A state file Agentmaster could not read is never replaced without its bytes kept** (PERSISTENCE.md §15). The loaders fail open, so "nothing saved" may stand in for a file that was locked, torn or BOM'd, and saving it would erase the user's state. ⚠ Every new state writer goes through `WriteAllUtf8` or the session store's `AtomicWriteUtf8` (both call `PrepareStateFileReplace`), and every new read-modify-write reads through `ReadStateFileUtf8` and writes nothing when the file is `Unreadable`.
17. **A bookmark TAG is removed only explicitly, and its color resolution is single-source.** Untagging a tag's last carrier never deletes the tag: the known-tag registry (`tags.json`) keeps it at ·0, and only the ✕ on a 0-carrier row deletes it (`UnregisterKnownTag`); a carried tag cannot be deleted. A deleted tag keeps its `tag-colors.json` entry, so a re-created name regains its color. Creating a name is capped by `AppSettings::maxTags`; applying or removing an existing tag never is. Every surface resolves a tag's color through `ResolveTagDisplayColor` (the user's pick > the name hash `TagColorFor`), and the tab badges and tooltip read the producer's resolved `AgentTagsSpec` (`name\t#AARRGGBB`) — never re-resolve per consumer, or one tag can wear two colors.
18. **Never lose a swallowed exception.** Every `catch (...)` reports the exception and its origin to `hooks.log`, so a later report is diagnosable without a repro; a catch may recover silently for the user, never for us.
    - Report through the one chokepoint: `Agentmaster::LogSwallowedException(L"<context>")` in the plain-C++ engine TUs (no WinRT: they compile in the harness and the CLI too), and `AgentLogCaughtException(context)` (`AgentCatchLog.h`) in the TerminalApp layer, which adds `hresult_error` / `wil` detail. Both attach the throw-site stack captured at raise time by the vectored exception handler, as `Module.dll+0xRVA` (a catch runs after the unwind, so that capture is the only copy of the stack).
    - Preserve every recovery side effect exactly (a re-armed latch, a fallback return, a `continue`): logging is additive, and behavior never depends on it (both reporters are `noexcept` and throttled).
    - Two narrow exemptions: a catch on the logging path itself stays bare, marked `⚠ DELIBERATELY BARE` with its degradation (Gotcha *The exception-forensics logging path*); a catch whose throw is expected control flow in a hot loop may stay bare, with a comment saying so. A "best-effort helper" is no exemption, and `OutputDebugStringW` does not count (it needs a debugger attached). Don't add a bare `catch (...)`.

## Conventions

- Mark our additions with `Agentmaster`.
- The repo `LICENSE` is **AGPL-3.0-or-later** (the combined work; the paid alternative is `LICENSE-COMMERCIAL.md`). Windows Terminal's **MIT** license stays in `LICENSE-MIT` and the third-party attributions in `NOTICE.md` (the source of the build's `NOTICE.html`) and `THIRD-PARTY-NOTICES.txt`: **never strip them** (MIT requires the notice). An external contribution needs a signed `CLA.md` before merge (the dual license depends on it).
- Keep the diff against upstream small where practical (additive files, small touches at integration points), so a rebase onto `microsoft/terminal` stays cheap.
- Build artifacts (`bin/`, `packages/`, `Generated Files/`) are gitignored: never commit them.

### The Agent Manager UI is ALWAYS dark, whatever the Windows or Windows Terminal theme

- Every Agentmaster surface root sets `RequestedTheme(ElementTheme::Dark)` — the Agent Manager page's `_root`, the Sessions page host, the settings / claude-missing / path-picker overlays — and paints an explicit dark fill (`_root` uses `#2e2e2e`). Never an app-theme-resolved brush: `Application.Resources().Lookup("UnfocusedBorderBrush")` resolves against the app theme and returns a light `#e8e8e8` in light mode, which shows through the gaps between the page's widgets.
- A confirm dialog that hosts itself (`AgentManagerContent`, `ShowAsync`) follows `_root.ActualTheme()`. A dialog shown through Windows Terminal's shared presenter (`TerminalWindow::ShowDialog`, which themes every dialog to the Terminal setting up its whole ancestor chain) opts into dark by the tag **`agentmaster-dark`** (the Sessions page's and the batch-close confirms carry it).
- Popups follow their anchor's theme: `MenuFlyout` context menus and `ComboBox` drop-downs take their target element's theme (as all of Windows Terminal's flyouts do), so menus and combos under `_root` need no per-flyout theming; the path-picker `Popup` is set dark explicitly.
- **Tooltips are the exception:** theme inheritance through `ToolTipService` is unreliable under XAML Islands, so `AgentSetTip` pins every tip dark.
- Don't add an app-theme-dependent brush or lookup on these surfaces; tag every new presenter-shown Agentmaster dialog `agentmaster-dark`; route every new tooltip through `AgentSetTip`.
